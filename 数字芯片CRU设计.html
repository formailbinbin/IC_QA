1. CRU 是什么

CRU（Clock and Reset Unit，时钟复位单元）是 SoC 里唯一集中管理时钟与复位两类全局信号的模块。它本身几乎不做数据处理，但所有模块能不能跑、跑多快、从什么状态开始跑，全由它决定。一旦 CRU 出错，表现往往不是"某个功能不对"，而是"整颗芯片不动了"，且难以在硅后用软件绕过。

1.1 六项核心职责

职责内容失效后果
时钟产生管理晶振、PLL/DPLL、环形振荡器，提供根时钟无时钟，芯片完全不工作
时钟分频整数/小数分频，派生各域工作频率频率错 → 时序违例或性能不足
时钟选择多源之间无毛刺切换（GMUX）毛刺 → 寄存器乱态，系统挂死
时钟门控模块级/功能级 ICG，关闭空闲时钟省动态功耗功耗超标，或门控误关导致模块失联
复位产生汇聚上电复位、看门狗、软复位、调试复位等源复位不全 → 启动随机失败
复位分发按复位域同步后分发，控制断言/去断言顺序异步去断言 → 亚稳态；顺序错 → 死锁

一句话定位：CRU 的输入是"少量根时钟 + 多种复位源 + 配置寄存器"，输出是"几十路成对的 clk_x / rstn_x"。设计的本质就是保证每一对输出在任何配置切换过程中都保持合法——时钟无毛刺、复位无亚稳态、二者关系满足去断言要求。

2.1 时钟通路框图

把时钟通路单独展开。注意一个重要约定：GMUX 放在分频之后、门控之前。这样切换时切的是已经分好频的稳定时钟，门控放最后则保证关断动作离负载最近、省功耗效果最好。

2.2 复位通路框图

复位通路的核心是三件事：汇聚（多源 OR）、同步（异步断言 + 同步释放）、排序（去断言的先后）。

POR ───────┐ PAD_RSTn ──┤ WDT_RST ───┼──► [OR 树] ──► [脉冲拉伸] ──► rst_global_async SW_RST ────┤ │ 保证 ≥ N 个 DBG_RST ───┘ │ 最慢时钟周期 │ └──► [原因锁存 RST_STATUS] ──► 软件读取判断上次为何复位 （W1C 清除，POR 才清零） rst_global_async │ ├──► 域 A 同步器（clk_ao 域） ──► rstn_ao ← 最先释放 ├──► 域 B 同步器（clk_periph） ──► rstn_periph ├──► 域 C 同步器（clk_bus） ──► rstn_bus ├──► 域 D 同步器（clk_cpu） ──► rstn_cpu ← 最后释放 └──► 域 E 同步器（clk_dbg） ──► rstn_dbg ← 独立，不受软复位影响 单个复位同步器（异步断言 / 同步释放，两级）： rst_async_n ──────────────┐ │（异步清零端） 1'b1 ──► ┌────┐ ┌────┐ │ │ DFF├───►│ DFF├───┴──► rstn_sync（同步释放） clk ────►│ CDN│ │ CDN│ └────┘ └────┘ ▲ ▲ └─────────┴── 两个 FF 的 CDN 都接 rst_async_n 【关键约束】 ① 断言（拉低）必须异步生效 —— 时钟没来也要能复位 ② 释放（拉高）必须同步于本域时钟 —— 否则所有 FF 同拍退出时亚稳态 ③ 同步器必须用本域时钟，禁止跨域复用同一个 rstn_sync ④ 复位期间该域时钟必须有效（至少 2~3 拍），否则同步器出不来

最常见的错误：把 rst_global_async 直接接到所有域的 FF 上，不做每域同步。仿真时 RTL 看不出问题（因为 RTL 的异步复位是理想的），但硅上会出现同一域内部分 FF 已退出复位、部分还在复位的状态，导致状态机进入非法态。这是 RDC（Reset Domain Crossing）检查的首要目标。

2.3 寄存器与总线接口

CRU 的寄存器不是普通的配置寄存器——写进去的值会改变寄存器自己赖以工作的环境，因此必须有一套"写入即握手"的协议，而不是简单的写完就生效。

寄存器类型行为要求
CLK_SELRW + busy写入后 busy=1，GMUX 完成切换后硬件清 0；busy 期间再写被忽略（或返回 error）
DIV_CFGRW + busy同上。分频比变更必须在输出低电平期对齐生效，禁止中途改计数上限
CLK_ENRW逐位门控使能。AO / DBG 对应位硬连线为 1，写入无效
SW_RSTW1S + 自清写 1 触发该域复位脉冲，硬件保证最小宽度后自动清 0。不允许写 1 后一直保持（否则软件自己把自己锁死）
RST_STATUSRO + W1C记录本次复位原因，POR 清零。软件读后 W1C，便于区分"冷启动/看门狗重启"
PLL_CTRLRWPLL 使能/倍频/power-down。当前正被使用的 PLL 不允许被关闭（硬件互锁）
CLK_STSROlock 状态、当前实际选中源、各域 clk 活动指示、切换超时标志

设计要点：所有"会导致自身环境变化"的写操作都要做成硬件互锁 + 握手 + 超时回退三件套。软件只能表达意图，是否安全由硬件判断。遵循这一条可以消掉 CRU 一大半的硅后致命风险。

不要一上手就写 RTL。CRU 的代码量不大但接口极多，先用一张表把所有时钟与复位输出定义清楚，评审通过后再实现，可以避免后期反复改接口。

1.2 时钟关系的三种处理方式

① 同源整数倍（推荐） clk_bus = clk_cpu / 2，同一 PLL 派生 ├─ 跨域可用同步桥，面积小延迟低 └─ SDC 中声明 generated clock，工具自动算关系 ② 同源非整数倍 clk_a = PLL/3，clk_b = PLL/5 ├─ 相位关系复杂但可枚举，仍可做"伪同步" └─ 时序分析需要考虑最坏对齐，预算要留足 ③ 异步（不同 PLL / 不同晶振） ├─ 必须用 CDC 结构（握手 / 异步 FIFO / 两级同步器） └─ SDC 中 set_clock_groups -asynchronous，否则时序报告全是假违例

实践建议：尽量让一个电压域内的所有时钟同源且整数倍。每多一组真异步关系，就多一套 CDC 结构、一组约束例外和一批验证场景。频率规划阶段多花一天，后面能省一周的 CDC 调试。

思路 3 · 分频器统一模板

一个 CRU 里往往有十几个分频器。写一个参数化模块，所有地方都实例化它，而不是每处手写一段计数器——后者是分频占空比错误的主要来源。

3.2 动态改分频比的正确做法

错误做法：计数器正在计数时直接改比较值。若新值小于当前计数值，计数器会一直计到溢出才翻转，产生一个超长的异常时钟周期，下游逻辑直接错乱甚至 setup 大违例。

正确做法：新分频比先写入影子寄存器，等当前分频周期结束（计数器归零、输出处于低电平）的那一拍再整体加载生效，同时给软件返回 div_busy。更稳妥的方案是"先门控该路时钟 → 改分频比 → 再开门控"，代价是几个周期的停顿。

  input              div_update,   // 写入脉冲
  output reg         div_busy,
  output             clk_out
);
  reg [W-1:0] div_r, div_shadow;
  reg [W-1:0] cnt;
  reg         clk_r;

  // 影子寄存器：先存起来，不立刻生效
  always @(posedge clk_in or negedge rstn)
    if (!rstn)           begin div_shadow <= 'd2; div_busy <= 1'b0; end
    else if (div_update) begin div_shadow <= div_cfg; div_busy <= 1'b1; end
    else if (load_en)    div_busy <= 1'b0;

  // 只在一个分频周期的边界加载新值
  wire load_en = div_busy && (cnt == 'd0) && (clk_r == 1'b0);

  always @(posedge clk_in or negedge rstn)
    if (!rstn)        div_r <= 'd2;
    else if (load_en) div_r <= div_shadow;

  always @(posedge clk_in or negedge rstn)
    if (!rstn) begin
      cnt <= 'd0; clk_r <= 1'b0;
    end else if (cnt == (div_r >> 1) - 1'b1) begin
      cnt <= 'd0; clk_r <= ~clk_r;          // 半周期翻转 → 50% 占空比
    end else begin
      cnt <= cnt + 1'b1;
    end

  assign clk_out = clk_r;
endmodule

分频输出是由触发器产生的时钟，综合时必须在 SDC 里用 create_generated_clock 声明，并确认该 FF 的输出被识别为时钟源、走时钟网络（CTS）而不是普通数据网络。漏声明会导致该域全部时序未被分析。

思路 4 · 无毛刺时钟切换

这是 CRU 最经典也最容易出事的部分。普通 MUX 切时钟会在切换瞬间产生窄脉冲（毛刺），这个毛刺宽度可能小于任何 FF 的最小时钟宽度要求，导致部分 FF 捕获到乱值——而且只在特定 PVT 和特定切换时刻出现，仿真极难复现。

4.1 毛刺是怎么产生的

普通 MUX 切换（错误）： clk_a ──┐_┌─┐_┌─┐_┌─┐_┌─ sel 在 clk_a 高、clk_b 低的瞬间翻转 clk_b ─┐__┌──┐__┌──┐__┌─ sel ──────┐▲ │└── 切换点 clk_out ──┐_┌┐ ┌──┐__┌──┐── ← 这里出现一个极窄的毛刺 ↑↑ 毛刺：宽度不可控，可能只有几十 ps GMUX 无毛刺切换（正确）： clk_out ──┐_┌─┐_______┌──┐__┌─ ↑ ↑ 先关断旧源 再开启新源 （保证有一段"静默期"，期间输出恒为 0，绝不出现窄脉冲）

4.2 标准 GMUX 结构

核心思路：每个源有一条"同步于自己时钟域的使能链"，每条链都必须先确认对方已经关断，自己才允许开启——这是一个互斥握手。

【分支 A】 【分支 B】 sel_a_req = sel & ~en_b_fb sel_b_req = ~sel & ~en_a_fb │ │ ▼ clk_a 下沿采样（两级，避免亚稳态） ▼ clk_b 下沿采样 ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ DFF │─►│ DFF │─► en_a │ DFF │─►│ DFF │─► en_b └─────────┘ └─────────┘ │ └─────────┘ └─────────┘ │ ▲ negedge clk_a │ ▲ negedge clk_b │ │ │ en_a ────────► [AND] ◄─┴── clk_a en_b ───► [AND] ◄── clk_b │ │ └──────────────► [OR] ◄─────────────────┘ │ clk_out 为什么用下沿采样 en？ → 保证 en 变化时对应的 clk 正处于低电平，AND 门输出不会被"截断"成毛刺 为什么要交叉反馈 en_a_fb / en_b_fb？ → 保证任一时刻最多一路 en 为 1，物理上杜绝两个源同时到输出

4.3 参考实现

module clk_gmux2 (
  input  clk_a, input rstn_a,
  input  clk_b, input rstn_b,
  input  sel,              // 0: 选 a   1: 选 b
  output clk_out,
  output sel_done          // 切换完成指示，给寄存器 busy 用
);
  reg a_en_q, a_en_qq;
  reg b_en_q, b_en_qq;

  // 分支 A：仅当 B 已确认关断，A 才允许开
  always @(negedge clk_a or negedge rstn_a)
    if (!rstn_a) begin a_en_q <= 1'b1; a_en_qq <= 1'b1; end   // 复位默认选 A（安全源）
    else begin
      a_en_q  <= ~sel & ~b_en_qq;
      a_en_qq <= a_en_q;
    end

  // 分支 B：仅当 A 已确认关断，B 才允许开
  always @(negedge clk_b or negedge rstn_b)
    if (!rstn_b) begin b_en_q <= 1'b0; b_en_qq <= 1'b0; end
    else begin
      b_en_q  <= sel & ~a_en_qq;
      b_en_qq <= b_en_q;
    end

  // 实际投片时这两个 AND + OR 必须用工艺库的 CKAND / CKMUX 单元，
  // 并在综合脚本里 set_dont_touch，防止被优化掉或替换成普通门
  assign clk_out  = (clk_a & a_en_qq) | (clk_b & b_en_qq);
  assign sel_done = sel ? b_en_qq : a_en_qq;
endmodule

4.4 必须补上的两个保护

保护没有会怎样怎么做
源活跃检测切到一个没有时钟的源，GMUX 的那条使能链永远不翻转，输出永久为 0，系统永久挂死用 AO 时钟对每个源做翻转计数，确认活跃后才允许被选中；寄存器层面做硬件互锁
切换超时回退软件以为切了，实际没切，且无任何提示AO 域计数器，N 个周期内 sel_done 未到，强制 sel 回退到安全源 + 置超时标志 + 中断

血的教训：切换到未使能的 PLL 是 CRU 最高频的硅后致命 Bug。表现为"芯片跑一段时间后在某次调频时彻底死掉，JTAG 也进不去"（因为 CPU 时钟停了）。必须由硬件拒绝非法切换，不能依赖软件自觉。

思路 5 · 时钟门控分层

时钟门控是动态功耗的主要抓手（时钟网络本身可占总动态功耗的 30%~40%）。

5.1 必须用 ICG 单元，不能手搓 AND

错误：assign clk_gated = clk & en; └─ en 在 clk 高电平期间变化 → 直接产生毛刺 正确：ICG（Integrated Clock Gating cell），内部是"低电平锁存 en" en ──► ┌──────────┐ │ Latch │ （clk 低时透传，clk 高时锁存） clk ──►│ (negL) ├─► en_latched ──┐ └──────────┘ ├─► [AND] ──► clk_gated clk ─────────────────────────────────┘ → en 的变化只在 clk 低电平期被采纳，输出永远是完整周期或完整静默，无毛刺 实现方式： ① 直接实例化工艺库单元（如 CKLNQD / PREICG），set_dont_touch ② 写标准可推断 RTL，让综合工具自动插入 clock gating cell
// 推荐写法：实例化封装模块，内部调库单元或可推断结构
module clk_gate_cell (
  input  clk_in,
  input  en,            // 功能使能
  input  test_en,       // scan_mode 时拉高，旁路门控
  output clk_out
);
  reg en_latch;
  always @(*)
    if (!clk_in) en_latch = en | test_en;   // 低电平透传
  assign clk_out = clk_in & en_latch;
endmodule

5.2 三层门控结构

层位置使能来源粒度说明
L1 全局CRU 内，GMUX 之后CLK_EN 寄存器 + PM 请求整个子系统省功耗最多；关之前必须确认该域已 idle
L2 模块模块时钟入口模块级 enable + local_idle单个 IP常用层级，与总线 idle 握手联动
L3 功能模块内部数据路径综合工具自动插入寄存器组由 if(en) q<=d 推断得到，收益稳定且零风险

5.3 关断前的 idle 握手

软件写 CLK_EN[i] = 0 │ ▼ CRU 发出 clk_off_req ────────► 目标模块 │ 检查：无未完成的总线事务 │ FIFO 空、FSM 在 IDLE ▼ CRU 收到 clk_off_ack ◄──────── 模块确认可以关 │ ▼ ICG 的 en 拉低（在 clk 低电平期生效）→ 时钟停止 │ ▼ CLK_STS 中该位置 0，软件可回读确认 若模块一直不 ack：超时 → 保持时钟开启 + 置 error 位，绝不强行关断

不做 idle 握手的后果：在总线事务进行中关掉从端时钟，从端永远不会返回响应，主端挂死在等待响应上，总线彻底卡住。这类 Bug 在随机压力测试中才会偶发出现，调试代价极高。

思路 6 · 复位域划分

复位域划分的原则：与时钟域对齐，但可以更粗。每个复位域对应一组"要么一起复位、要么一起工作"的逻辑。

6.1 复位矩阵（必须显式列出）

复位域PORPAD_RSTnWDTSW_RST_SYSSW_RST_<IP>DBG_RST
rstn_ao✔✔✘✘✘✘
rstn_cpu✔✔✔✔✘✔
rstn_bus✔✔✔✔✘✘
rstn_periph✔✔✔✔✔✘
rstn_ddr✔✔✔可选✘✘

看这张表要确认三件事：① AO 域不被软复位影响（否则软件一复位就把 CRU 自己的配置清掉了）；② 调试域不被看门狗和软复位影响（否则系统反复重启时调试器会被踢掉，无法抓现场）；③ DDR 域的复位要和训练流程配合（训练完成后复位会丢失训练结果，需要重训或保持）。

6.2 复位源的最小宽度保证

外部 PAD 复位、WDT 复位都是异步到来，宽度不可控。必须拉伸到足够覆盖最慢时钟域的若干个周期，否则慢时钟域可能完全采不到这次复位。

// 复位拉伸：用最慢的 always-on 时钟计数
module rst_stretch #(parameter N = 16) (
  input  clk_ao, input rst_in_n, output rst_out_n
);
  reg [$clog2(N):0] cnt;
  always @(posedge clk_ao or negedge rst_in_n)
    if (!rst_in_n)      cnt <= N;            // 异步断言，立刻装载
    else if (cnt != 0)  cnt <= cnt - 1'b1;   // 同步倒数
  assign rst_out_n = (cnt == 0);
endmodule

思路 7 · 复位同步与释放顺序

7.1 异步断言 / 同步释放

这是整个数字设计里最标准、也最不能走样的一个结构。

module rst_sync (
  input  clk,
  input  rst_async_n,    // 异步复位输入（低有效）
  input  test_mode,      // scan 时直通，保证 scan 链可控
  output rstn_sync
);
  reg q1, q2;
  always @(posedge clk or negedge rst_async_n)
    if (!rst_async_n) begin q1 <= 1'b0; q2 <= 1'b0; end  // 异步断言
    else              begin q1 <= 1'b1; q2 <= q1;      end  // 同步释放
  assign rstn_sync = test_mode ? rst_async_n : q2;
endmodule
clk ─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─ rst_async_n ──┐________________┌────── ↑ 立即生效 ↑ 异步抬起 （不等时钟） │ q1 ──┐_________________┌───── ← 第一拍 q2 = rstn ──┐__________________┌──── ← 第二拍，对齐时钟沿 断言：异步 —— 没有时钟也能复位（关键！门控期间也要能复位） 释放：同步 —— 全域 FF 在同一个时钟沿整齐退出，无亚稳态、无部分退出
错误写法后果
纯同步复位（always @(posedge clk) if(!rstn)）时钟没来时无法复位；门控/上电初期失效
纯异步复位，不加同步器释放时刻随机，恢复时间（recovery/removal）违例，FF 部分退出复位 → 状态机非法态
一个同步器的输出给多个时钟域用对其他域而言仍是异步释放，等于没做同步；RDC 检查会报错
同步器自己用的时钟是被门控的门控关闭时复位无法释放 → 死锁（见难点 15.2）

7.2 释放顺序 FSM

复位断言可以同时（全部拉低无所谓），但释放必须有序：被依赖的先活，依赖者后活。

POR 到来 → 全部域 rstn 拉低 │ ▼ [S0] 等 XTAL 稳定（计数器，典型几 ms） │ ▼ [S1] 释放 rstn_ao ───► CRU 自身寄存器、PM 控制器开始工作 │ ▼ [S2] 释放 rstn_dbg ───► 调试器可以接入了（越早越好，便于抓启动问题） │ ▼ [S3] 等 PLL lock（或直接用 XTAL 启动，后续再切 PLL） │ ▼ [S4] 释放 rstn_periph / rstn_ddr ───► 从端设备先就绪 │ ▼ [S5] 释放 rstn_bus ───► 互联就绪（从端已 ready，不会收到无人应答的请求） │ ▼ [S6] 释放 rstn_cpu ───► CPU 最后出复位，取第一条指令时整个系统已就绪 │ ▼ [RUN] 正常运行 每一级之间插入若干个时钟周期的间隔（可配置），保证上一级确实稳定

顺序错了的典型现象：CPU 先出复位，立刻取指访问总线，但总线还在复位中 → 请求无响应 → CPU 挂在第一条指令上。这种问题在 FPGA 上可能因为时序不同而偶尔跑通，极具误导性。务必按"从端 → 互联 → 主端"的顺序释放。

思路 8 · 寄存器与握手协议

CRU 的寄存器接口设计有一条独特约束：它要在自己可能被改变的环境里保证访问不丢、不卡。

8.1 三类写操作与对应协议

写操作风险协议
改分频比 / 换时钟源过程中输出时钟不稳定busy 握手：写入 → busy=1 → 硬件完成 → busy=0；busy 期间拒绝新写
关闭某域时钟可能关掉正在工作的模块idle 握手 + 超时：模块 ack 后才真关
触发软复位可能把自己复位掉W1S + 硬件自清 + AO 域互锁（不允许复位 AO/DBG）

8.2 跨时钟域的寄存器访问

CRU 寄存器在 AO 域（如 24 MHz），而配置总线可能在 bus 域（如 300 MHz）。两者异步且频率差很大，必须做 CDC：

APB (clk_bus, 300MHz) CRU CSR (clk_ao, 24MHz) ──────────────────────── ─────────────────────────── psel/penable/pwrite ──┐ paddr/pwdata ─────────┤ ▼ ┌───────────┐ req ┌───────────┐ │ 请求打包 ├──────►│ 两级同步器├──► 在 AO 域执行读写 │ (单次事务)│ └───────────┘ │ └───────────┘ ▼ ▲ ack ┌───────────┐ ┌───────────┐ pready ◄──────────────┴──────────────┤ 两级同步器│◄─┤ 完成应答 │ prdata ◄───────── 数据随 ack 稳定取回 └───────────┘ └───────────┘ 要点： ① 用请求-应答握手，不要对每个寄存器位做独立同步（多位同步会出现采样错位） ② 数据总线不单独同步，而是在 ack 到达时"数据已稳定多拍"的前提下直接取 ③ APB 需要容忍较长的 pready 等待（慢时钟域往返 ≥ 4~6 个慢时钟周期）

思路 9 · 低功耗与 DVFS 配合

9.1 频率与电压变更的顺序

升频（先升压，后升频）： 降频（先降频，后降压）： ① 请求 PMIC 升电压 ① 切到低频时钟 ② 等电压稳定（ack / 延时） ② 等切换完成 busy=0 ③ 切到高频时钟 ③ 请求 PMIC 降电压 ④ 等切换完成 ④ 等电压稳定 原则：任何时刻都保证"当前电压 ≥ 当前频率所需的最低电压" 违反后果：低电压跑高频 → 全芯片时序违例 → 随机死机（且温度/批次相关，极难定位）

9.2 低功耗模式的时钟复位行为

模式时钟复位CRU 需要做的
WFI / IdleCPU 时钟自动门控保持中断到来时立刻恢复时钟（纯硬件路径，< 几个周期）
Light SleepPLL 关，XTAL 保留保持唤醒时重新等 PLL lock 再切回
Deep Sleep仅 32 kHz 保留AO 保持，其余断言唤醒逻辑只能用 32 kHz；唤醒后走完整的复位释放 FSM
Power Off 域无域内全部复位上电顺序：供电 → 时钟 → 解除隔离 → 释放复位（顺序反了会打坏逻辑）

唤醒通路的致命陷阱：唤醒检测逻辑如果用的是被关掉的时钟，那就永远醒不过来。唤醒路径必须完全放在 AO 域，且用永不关断的时钟（或纯异步组合逻辑）。这条和中断设计里"唤醒通路不依赖可被关闭的时钟"是同一条规则。

特性实现解决什么问题

这一条的价值常被低估。CRU 的硅后问题往往表现为"芯片不动了"，没有任何软件可读的信息。多花几百个门做频率计和存活指示，能把定位时间从几周缩短到几小时。

15. 难点深入分析

15.1 切换时源时钟消失

这是 GMUX 最经典的死穴。GMUX 的握手逻辑依赖两个源时钟都在跳：关断分支 A 需要 clk_a 的边沿，开启分支 B 需要 clk_b 的边沿。

时刻 T0：当前使用 clk_pll（300MHz），软件写 CLK_SEL = XTAL 时刻 T1：GMUX 在 clk_pll 下沿关断 A 分支 → clk_out 静默 时刻 T2：需要 clk_xtal 的边沿来开启 B 分支 ★ 如果此刻 XTAL 因为 PAD 虚焊 / 晶体没起振 / 被误关 → clk_xtal 永远不跳 → B 分支永远打不开 clk_out 永久为 0 → CPU 停摆 → 软件无法补救 看门狗也在这条时钟上 → 连复位都出不来

反过来也一样：如果软件先把 PLL 关了再去切走 PLL，那关断 A 分支所需的 clk_pll 边沿也不存在，GMUX 会卡在"既没关完也没开"的中间态。

三层防御：

层次机制说明
事前源活跃检测每个源用 AO 时钟做翻转检测，src_alive[i]；目标源 alive=0 时硬件直接拒绝这次切换，置 SEL_ERR
事中切换超时回退AO 域计数器，发起切换后 N 个 AO 周期内 sel_done 未回 → 强制 sel 回到原值或安全源
事后独立看门狗WDT 必须挂在 AO 时钟（或独立 RC），不能和被切换的时钟共命运，否则救不了场

反面做法：只在软件驱动里写"切换前请先确认目标时钟已使能"。软件约定不是设计，现场一定有人违反它——尤其是异常路径和 ROM 代码。

15.2 门控与复位的死锁

复位同步器需要时钟才能完成"同步释放"（两级 FF 要打两拍）。如果喂给它的时钟本身是被门控的，而门控的使能又来自这个复位域内的寄存器，就形成了闭环：

┌─────────────────────────────────────────────┐ │ │ ▼ │ rst_sync 需要 clk_mod 打两拍 │ │ │ ▼ │ rstn_mod 释放 │ │ │ ▼ │ 模块内 CLK_EN 寄存器才能被写 1 │ │ │ ▼ │ ICG 使能打开，clk_mod 才有波形 ──────────────────────┘ ★ 环路闭合 → 谁也起不来 → 模块永久复位中

解法（按优先级）：

方案做法评价
A（推荐）复位同步器用门控前的时钟（ungated clock）彻底打破环路；代价是多走一条未门控时钟线，CTS 要单独平衡
BICG 使能 en = sw_en | ~rstn_mod复位期间强制开时钟，释放后交回软件；简单但复位期间有动态功耗
CCLK_EN 寄存器放在 CRU 内（属 rstn_ao 域）控制寄存器与被控对象不同域，天然无环；这也是"配置寄存器集中在 CRU"的理由之一

同类死锁还有一个变种：软复位寄存器自己被自己复位。SW_RST 写 1 后若该寄存器也在被复位的域内，复位一断言寄存器立刻清 0，复位脉冲宽度不可控，可能窄到某些慢速域根本采不到。解法是 SW_RST 寄存器必须在 AO 域，并配 rst_stretch 保证最小宽度。

15.3 复位去断言顺序

复位断言（assert）可以乱序，因为那时电路不工作；复位释放（de-assert）必须严格有序。两个层面的问题：

（1）系统层面：功能顺序

错误顺序：rstn_cpu 先释放，rstn_periph 还在复位 → CPU 取完第一条指令就去访问 UART → UART 在复位中不回 ready → AHB/AXI 事务永久挂起 → CPU 卡在第一条 load 上 正确顺序（从端 → 互联 → 主端）： XTAL 稳定 → rstn_ao → rstn_dbg → PLL lock → rstn_periph / rstn_ddr → rstn_bus → rstn_cpu （从设备） （互联） （主设备）

（2）电路层面：recovery / removal

即使顺序对，同一个复位信号到达不同 FF 的时间不同（高扇出、长走线）。若释放沿与时钟有效沿过近，部分 FF 已经离开复位、部分还没有，一拍之内电路处于半复位状态，FSM 可能直接跳进非法状态。

检查项含义保证手段
Recovery time复位释放沿必须早于时钟沿至少 trec同步释放 + STA 中 check_timing 覆盖异步复位端口
Removal time复位释放沿必须晚于时钟沿至少 trem同上
Reset tree skew复位网络到达各 FF 的偏差后端做 reset tree synthesis，或把复位当高扇出网络专门平衡

很多团队只做了"异步断言同步释放"就认为复位安全了。同步释放只保证了跨域的那一跳，释放后的复位信号在域内仍是一条高扇出网络，仍然要在 STA 里被正常 setup/hold 检查——这要求它被当作普通数据信号约束，而不是 set_false_path 一刀切掉。

15.4 CDC 与约束爆炸

CRU 是全芯片时钟最复杂的地方：N 个源 × M 个分频比 × K 个 MUX，组合出的时钟数量很容易过百。

问题一：SDC 组合爆炸

clk_sys MUX 有 4 个源，每个源后面 8 档分频 → 32 个 generated clock 定义在同一个节点上 → STA 默认认为它们"同时存在"且"相互有关系" → 分析 32×32 组跨时钟路径，其中 99% 物理上不可能发生 → 跑不完、修不完、全是假违例
手段作用注意
set_clock_groups -physically_exclusive声明同一 MUX 的多个源不会同时出现必须与 GMUX 实际行为一致，否则漏检真实路径
set_case_analysis + 多 mode 签核每个工作模式固定一组 sel/div，分别签核模式清单要穷举，漏一个模式=漏一片时序
set_clock_groups -asynchronous真正异步的域之间不做 setup/hold只能用在已有 CDC 同步器的路径上

最危险的误用：把 -asynchronous 当成"消违例神器"，给两个其实同源的域也加上。结果是这组路径从此再也不被检查，流片后随机出错，且 STA 报告一片绿。

问题二：CRU 自身的 CDC

CRU 的寄存器在 bus 域（如 300MHz），而 GMUX 握手、超时计数、源活跃检测在 AO 域（如 24MHz）。两者之间必须正规 CDC：

信号方向内容同步方式
bus → AO切换请求 sel_req / 新的 sel 值req 用脉冲→电平+两级同步；sel 值作为数据，由 req 握手保证稳定后才采，不单独同步
AO → bussel_done / busy / timeout两级同步器；多 bit 状态用格雷码或同样走 req/ack

口诀：控制信号同步，数据信号握手。多 bit 配置值绝不逐 bit 过同步器（会出现各 bit 到达时刻不同导致的中间值，直接打到 MUX 选择端就是毛刺）。

15.5 自举与启动顺序

上电瞬间的"鸡生蛋"问题：CRU 需要时钟才能工作，而时钟正是 CRU 产生的；CRU 需要复位才能初始化，而复位分发也是 CRU 做的。

上电启动链（每一步只能依赖已经稳定的前一步） VDD 上升 │ ▼ ① POR（模拟电路，纯模拟，不需要任何数字时钟） │ 产生 por_n，是整个数字系统唯一的"原始复位" ▼ ② XTAL 起振 —— 需要 ~ms 级稳定时间 │ 用 AO 域一个简单计数器等待（计数器由 XTAL 自己驱动， │ 在起振前它不计数，天然满足"起振后才开始计时"） ▼ ③ rstn_ao 释放 —— CRU 自己的控制逻辑开始工作 │ ▼ ④ CRU FSM 配置并启动 PLL，等 lock（lock 要同步+稳定计数） │ ▼ ⑤ 按既定顺序释放 rstn_periph / rstn_bus / rstn_cpu │ ▼ ⑥ CPU 从 ROM 取第一条指令（此时跑在 XTAL 或低档分频上） │ ▼ ⑦ 软件接管：提频、开各域时钟、配 DVFS
难点后果对策
XTAL 稳定时间不可综合地"知道"等待不足 → 时钟频率不准、PLL 锁不住计数器长度可配（默认取最坏晶体规格），上电用默认值，软件后续可调优
PLL lock 信号抖动误判已锁 → 切过去就失锁 → 挂死lock 两级同步 + 连续稳定 N 周期计数，lock_stable 才是真锁
Boot 时钟选择默认跑太快 → ROM 读不出；太慢 → 启动时间长复位默认值必须是最保守的安全配置（XTAL 直出或大分频）
Flash/DDR 的时序与频率绑定提频后外存访问超时提频前先改外存控制器的 latency 配置，顺序由软件 BSP 固化并在 CRU 寄存器上加互锁

复位默认值（reset value）是 CRU 最重要的一组常量。它们决定了芯片"睁开眼睛时是什么样子"。评审时要逐个寄存器确认：如果软件一行都不跑，这套默认配置能不能让芯片安全地停在那里？答案必须是能。

第四部分 · 怎么验证

CRU 的验证难点在于：它的大部分 bug 不是"数据错"，而是"时钟没了 / 复位没放开 / 顺序反了"。仿真波形里经常看不到 X，只是一片平直——所以必须靠断言和覆盖率主动去抓，不能靠肉眼看波形。

17. 验证整体策略

CRU 没有任何单一手段能验完，必须四层叠加，每层抓不同类型的问题。

13DVFS 升降频完整序列升频前已升压、降压前已降频；互锁生效；非法顺序被硬件拒绝
14scan_mode 断言所有 ICG 旁路、GMUX 选 scan 时钟、复位直通
15寄存器非法写入busy 期间写入被忽略/拒绝；非法组合被拦截；不产生内部死锁

用例 4、5、6、8 是异常注入类，也是最容易被忽略的。它们的通过标准不是"功能正确"，而是"系统没有挂死且留下了可读的错误记录"。

18.3 随机压力验证

定向用例覆盖的是"已知的路径"，随机压力负责撞出"没人想到的组合"。

随机维度随机内容约束
配置序列随机顺序写 CLK_SEL / DIV_CFG / CLK_EN / SW_RST不加任何"软件应该怎么做"的约束，就是要撞非法顺序
时间点在任意时刻（包括 busy 中、复位中、切换中）发起新操作间隔随机，含背靠背连续写
外部事件随机注入 PLL 失锁、XTAL 停振、WDT 超时、下游不回 ack可与配置操作重叠
复位在任意时刻注入各级复位包括"切换进行到一半时复位"

随机验证的核心价值场景："软件在 GMUX 正在切换的中途又写了一次 CLK_SEL"、"关断握手还没回 ack 就来了软复位"。这类交叠场景人工几乎想不全，但在硅片上一定会发生。

18.4 关键 SVA 断言

断言是 CRU 验证的主力——因为很多错误的表现是"什么都没发生"，只有断言能把它变成一次失败。

// ① 无毛刺：输出时钟的高/低电平宽度不得小于最快源的半周期
property p_no_glitch;
  @(posedge clk_out) ($time - $past(clk_out_edge_time)) >= T_MIN_HALF;
endproperty
// 实际常用更直接的写法：在 monitor 里用 realtime 记录上一次跳变，
// 任何间隔 < T_MIN 立刻 `uvm_error

// ② GMUX 使能互斥：任何时刻两路分支不得同时开启
property p_gmux_exclusive;
  @(posedge clk_ref) disable iff (!rstn_ao)
    !(a_en_qq && b_en_qq);
endproperty

  else $error("GMUX 两路同时使能，必然产生毛刺");

// ③ 切换必达：发起切换后，有限周期内必须完成或超时回退
property p_switch_liveness;
  @(posedge clk_ao) disable iff (!rstn_ao)
    $rose(sel_req) |-> ##[1:TIMEOUT_N] (sel_done || sel_timeout);
endproperty
assert property (p_switch_liveness)
  else $error("切换既没完成也没超时，系统静默挂死");

// ④ 复位释放顺序：rstn_cpu 释放时，rstn_bus 必须已经释放
property p_rst_order_cpu_after_bus;
  @(posedge clk_ao) disable iff (!por_n)
    $rose(rstn_cpu) |-> rstn_bus;
endproperty
assert property (p_rst_order_cpu_after_bus)
  else $error("CPU 复位先于总线释放，首次访问必挂");

// ⑤ 复位最小宽度：任何 rstn 断言后必须保持至少 N 个目标域周期
property p_rst_min_width;
  @(posedge clk_mod) $fell(rstn_mod) |-> !rstn_mod [*MIN_CYC];
endproperty

// ⑥ 时钟存活：非低功耗模式下，关键时钟不得连续 N 周期无跳变
property p_clk_alive;
  @(posedge clk_ao) disable iff (!rstn_ao || low_power_mode)
    clk_cpu_toggle_cnt_changed;
endproperty

// ⑦ 未锁定不得使用：PLL 未 lock_stable 时，功能时钟不得选中 PLL
property p_no_unlocked_pll;
  @(posedge clk_ao) disable iff (!rstn_ao)
    (cur_sel == SEL_PLL) |-> lock_stable;
endproperty

// ⑧ 关断前必须 idle：时钟被关断时，该模块必须已回 ack
property p_gate_after_idle;
  @(posedge clk_ao) disable iff (!rstn_ao)
    $fell(clk_en_mod) |-> $past(clk_off_ack);
endproperty

// ⑨ busy 期间配置不变：busy=1 时内部生效的配置值不得改变
property p_cfg_stable_in_busy;
  @(posedge clk_bus) disable iff (!rstn_bus)
    busy |-> $stable(div_r_effective);
endproperty

断言 ③ 是 liveness（必达性） 类，最关键也最容易被遗漏。CRU 的致命 bug 多数表现为"卡住了"，而不是"值错了"——没有必达性断言，仿真会显示"通过"，因为它确实没报任何错，只是什么都没再发生。

19.3 时钟建模：超采样法

这是整个 CRU formal 最核心的技术点，做错了后面全是假阳性。

错误做法：用 create_clock clk_a -period 10 和 create_clock clk_b -period 7 声明两个源时钟。这样工具只会按这一组固定的频率比和相位关系去验证。而 GMUX 的 bug 恰恰藏在病态相位里——比如两个时钟沿只差 1ps 的那一瞬间。你证明通过的只是"在 10:7 这个特定相位下没问题"，而不是"所有情况下都没问题"。

正确做法：把时钟降格为数据。引入一个超采样时钟 clk_fast 作为整个形式环境中唯一的 create_clock，把 clk_a / clk_b 变成自由输入信号，只用 assume 约束它们的最小高/低电平宽度。这样形式引擎会穷举两者的所有频率比与所有相位关系。

clk_fast ┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─┐_┌─ 唯一的 create_clock clk_a ───────┐ ┌───────────┐ 自由信号 └───────────────┘ └────── 仅约束最小宽度 >= MINW clk_b ───┐ ┌───┐ ┌───┐ ┌─── 自由信号 └───────┘ └───────┘ └───────┘ 仅约束最小宽度 >= MINW ★ 形式引擎会枚举 clk_a / clk_b 所有满足最小宽度约束的波形组合 → 包含所有频率比、所有相位差、包括最恶劣的临界对齐

第二个核心转换：形式工具不认识"毛刺"。形式验证是周期级的，毛刺是亚周期现象，没法直接写 assert(无毛刺)。必须把它翻译成周期级的等价命题。毛刺的物理成因只有一个——使能信号在对应时钟为高电平时发生跳变。所以证下面三条，就等价于证了无毛刺：

编号命题形式表达
P1两路使能恒互斥!(a_en && b_en)
P2使能只在对应时钟低电平期间跳变$changed(a_en) |-> $fell(clk_a)
P3输出严格等于被选中源，静默期为干净 0a_en |-> (clk_out == clk_a)

形式建模 wrapper（只用于 formal，不参与综合）：

// fml_gmux_env.sv —— 仅用于形式验证
module fml_gmux_env #(parameter MINW = 2) (input clk_fast);

  // clk_a / clk_b / sel / rstn 都是自由信号，由形式引擎任意驱动
  logic clk_a, clk_b, rstn, sel;
  logic clk_out, sel_done;

  // ① 约束：源时钟必须是"物理上合法的时钟"
  //    高电平和低电平都至少维持 MINW 个 clk_fast 周期
  //    这是在建模现实，不是在放水
  property p_min_width(sig);
    @(posedge clk_fast) $changed(sig) |=> $stable(sig)[*MINW-1];
  endproperty
  am_clka_width : assume property (p_min_width(clk_a));
  am_clkb_width : assume property (p_min_width(clk_b));

  // ② 约束：两个源都在持续翻转（证 liveness 的必要前提）
  //    注意：这条 assume 恰恰对应 15.1 节的"源时钟消失"风险——
  //    形式里假设它活着，所以"源死了"这个场景必须由仿真去覆盖
  am_clka_live : assume property
      (@(posedge clk_fast) ##[1:4*MINW] $changed(clk_a));
  am_clkb_live : assume property
      (@(posedge clk_fast) ##[1:4*MINW] $changed(clk_b));

  // ③ DUT：RTL 中的 always @(negedge clk_a) 保持原样不改，
  //    clk_a 作为自由信号时，其 negedge 由引擎穷举产生
  clk_gmux2 u_dut (
    .clk_a(clk_a), .rstn_a(rstn),
    .clk_b(clk_b), .rstn_b(rstn),
    .sel(sel), .clk_out(clk_out), .sel_done(sel_done)
  );
endmodule

为什么 am_clk*_live 这条 assume 必须存在：liveness 属性（"最终一定完成"）在源时钟可以永远不跳的前提下是不成立的——这正是 15.1 节描述的真实风险。形式验证在这里的角色是证明"在源时钟正常的前提下，握手逻辑本身没有死锁"；而"源时钟异常"的场景属于仿真的异常注入用例（18.2 节用例 5）。两者分工明确，不能互相替代。

      ( @(posedge clk_bus) disable iff (!rstn)
        req_bus && !ack_bus_sync |-> $stable(data_bus) );

  // ② AO 侧采样时刻数据必定已稳定（证明不会采到中间值）
  as_capture_ok  : assert property
      ( @(posedge clk_ao) disable iff (!rstn)
        $rose(req_ao_sync) |=> (data_ao_captured == $past(data_bus, 3)) );

  // ③ 握手必定完成（liveness）
  as_hs_live     : assert property
      ( @(posedge clk_bus) disable iff (!rstn)
        $rose(req_bus) |-> s_eventually (ack_bus_sync) );

  // ④ 四相握手协议不乱序
  as_protocol    : assert property
      ( @(posedge clk_bus) disable iff (!rstn)
        $fell(req_bus) |-> $past(ack_bus_sync) );
endmodule

19.6 约束管理与过约束陷阱

形式验证最危险的失败模式不是"证不出来"，而是"证出来了但结论无效"。根源是 assume 写得过紧，把设计约束到根本动不了，于是所有 assert 都"通过"——实际上一条路径都没走过。

典型的过约束事故：为了让 liveness 收敛，加了一条 assume (sel == 1'b0)。结果 GMUX 从来没切换过，所有无毛刺属性都 trivially pass，报告一片绿。这种"证明"比不做形式验证更危险，因为它给了虚假的信心。

防护手段做法强制程度
先跑 cover在 check_fv -block 之前先 check_fv -cov，所有 cover property 必须 covered强制
过约束分析VC Formal 的 check_fv -overconstraint / JasperGold 的 check_assumptions强制
assume 清单评审每条 assume 写明：为什么现实中成立？谁来保证？强制
assume 转 assert子模块的 assume 必须在上层变成 assert 被证明强烈建议
assume 带到仿真把 formal 的 assume 编译进 UVM 环境当 assert 跑强烈建议

CRU formal 的 assume 清单（每条都必须有归属）：

assume内容现实中由谁保证
am_clk*_width源时钟最小高/低电平宽度物理事实（PLL/晶振的规格）
am_clk*_live源时钟持续翻转不保证！由仿真异常注入用例覆盖（18.2 用例 5）
am_sel_stable切换期间 sel 不再变上层寄存器 busy 互锁 → 在 19.4.5 中被 assert 证明
am_div_legaldiv_cfg 为偶数且 ≥ 2寄存器写入过滤 → 在 19.4.5 中被 assert 证明
am_xtal_ok晶振最终稳定物理事实 + 启动计数器；失效场景由仿真覆盖
am_pll_okPLL 最终锁定不保证！失锁场景由仿真覆盖（18.2 用例 6）

这张表本身就是 formal 与仿真的分工协议。凡是标注"不保证"的 assume，都对应一个必须存在的仿真异常注入用例。两份验证计划通过这张表对齐，不会出现"两边都以为对方验了"的缺口。

19.7 收敛技巧

技巧做法适用场景
黑盒PLL、晶振、SRAM、第三方 IP 全部 set_blackbox，行为用 assume 描述顶层必用
Cut point在分频器输出、计数器输出打 cut point，让其变成自由信号切掉大状态空间

对称约简4 选 1 GMUX 树只证一对 + 对称性论证重复结构

缩参数为什么是合法的：形式工具对宽计数器极度敏感，一个 16bit 超时计数器就能让 liveness 证明永远跑不完。把它缩到 3bit 证明逻辑，是标准做法——因为你要证的是「超时机制存在且行为正确」，而不是「1024 这个数值是否合适」。后者属于仿真和系统分析的范畴。缩参数后必须在报告中明确记录原参数与缩减参数。

19.8 形式签核标准

形式验证的结论有四种状态，只有分清它们才能判断是否真的验完了。

形式验证在 CRU 上的独特价值：它能给出反例波形。当工具证明"存在一种 sel 翻转时机导致毛刺"时，会直接给出那个精确到亚周期的序列——这种序列随机仿真跑一万次也可能撞不到一次。CRU 的致命 bug 几乎都属于这类"极窄时间窗"问题，这正是形式验证不可替代的地方。

19.9 静态检查清单

工具类别检查内容必须零违例的项

常见的坏习惯：把 CDC 工具报出的几百条违例用 waiver 批量关掉。CRU 的 CDC 路径本来就不多（几十条量级），每一条都应该被人看过并写明理由。批量 waiver = 放弃这道防线。

CI 集成建议：Lint / CDC / RDC 和 L1 层的叶子单元 FPV（GMUX、分频器、复位同步器）跑完都在分钟级，应当配置为每次 RTL 提交自动运行，不通过不许合入。L2/L3 的 FPV 与 CC 跑夜间回归。这套自动化的建设成本很低，但能在 CRU 上挡住绝大多数结构性错误。

20. 覆盖率模型

CRU 的覆盖率必须自己定义——代码覆盖率 100% 对 CRU 几乎没有意义（所有行都会被执行到），真正的风险在"组合"和"交叠时机"。

20.1 功能覆盖点

covergroup cg_cru @(posedge clk_ao);

  // ① 时钟源选择：每个 MUX 的每个源都被选中过
  cp_sel_sys  : coverpoint cur_sel_sys  { bins all[] = {[0:N_SRC-1]}; }

  // ② 切换矩阵：源 → 目标 的所有组合（最重要的交叉）
  cp_sel_from : coverpoint prev_sel_sys;
  cp_sel_to   : coverpoint cur_sel_sys;
  cross_switch: cross cp_sel_from, cp_sel_to {
      ignore_bins same = binsof(cp_sel_from) intersect {0} &&
                         binsof(cp_sel_to)   intersect {0};
  }

  // ③ 分频比：边界值 + 典型值 + 奇偶
  cp_div : coverpoint div_cfg {
      bins min    = {2};
      bins max    = {MAX_DIV};
      bins odd[]  = {3,5,7,9};
      bins even[] = {4,6,8,16,32};
  }

  // ④ 分频 × 时钟源 交叉（有些组合会超出下游频率上限）
  cross_div_src : cross cp_div, cp_sel_sys;

  // ⑤ 复位源 × 复位域（复位矩阵的全覆盖）
  cp_rst_src : coverpoint rst_source { bins all[] = {POR,WDT,SW,PIN,LOCKUP}; }
  cp_rst_dom : coverpoint rst_domain { bins all[] = {AO,DBG,CPU,BUS,PERIPH,DDR}; }
  cross_rst  : cross cp_rst_src, cp_rst_dom;

  // ⑥ 门控：每一路时钟的开 → 关 → 开
  cp_gate : coverpoint clk_en_vec { bins each[] = ...; }

  // ⑦ 异常场景
  cp_err : coverpoint err_event {
      bins pll_unlock    = {ERR_PLL_UNLOCK};
      bins sel_timeout   = {ERR_SEL_TIMEOUT};
      bins gate_timeout  = {ERR_GATE_TIMEOUT};
      bins illegal_cfg   = {ERR_ILLEGAL_CFG};
      bins src_dead      = {ERR_SRC_DEAD};
  }

  // ⑧ 低功耗模式 × 唤醒源
  cp_lp   : coverpoint lp_mode   { bins all[] = {IDLE,LIGHT,DEEP,OFF}; }
  cp_wake : coverpoint wake_src  { bins all[] = {[0:N_WAKE-1]}; }
  cross_lp: cross cp_lp, cp_wake;

endgroup

20.2 时序交叠覆盖点

这类覆盖点无法用普通 coverpoint 表达，要用 cover property：

// ① 在切换进行中再次发起切换
cover property (@(posedge clk_ao) busy ##0 $rose(sel_req));

// ② 在切换进行中来了复位
cover property (@(posedge clk_ao) busy ##0 $fell(rstn_bus));

// ③ 在关断握手等待 ack 期间，模块又发起了新事务
cover property (@(posedge clk_ao) clk_off_req && !clk_off_ack ##0 new_trans);

// ④ PLL 失锁恰好发生在切换到 PLL 的过程中
cover property (@(posedge clk_ao) (sel_req && sel_to_pll) ##[0:10] pll_unlock);

// ⑤ 改分频比与改时钟源背靠背
cover property (@(posedge clk_bus) $rose(div_update) ##[1:3] $rose(sel_req));

// ⑥ 软复位脉冲与低功耗进入重叠
cover property (@(posedge clk_ao) sw_rst_pulse ##0 lp_enter_req);

覆盖率收敛策略：先用定向用例把"矩阵类"覆盖点（切换矩阵、复位矩阵）打满，再用随机跑"时序交叠类"。后者往往需要几千到几万次随机种子才能收敛，但正是它们对应着最难查的现场问题。
