芯片实现全流程

从 Spec 到量产 · 前端设计 / 综合 DFT / 后端物理实现 / 流片

第一章　前端设计

1规格定义（Spec）

确定功能、性能、功耗、面积（PPA）、接口协议、工艺节点，产出架构文档。
产出：Spec 文档、PPA 目标

2架构设计（Architecture）

  • 模块划分、总线结构选型
  • 时钟域 / 复位域规划
  • 存储层次设计、流水线级数划分

3RTL 设计

用 Verilog / SystemVerilog / VHDL 实现逻辑。
  • 关注可综合性（避免不可综合写法）
  • 跨时钟域处理（CDC）：同步器、异步 FIFO、握手
  • 复位策略：同步复位 / 异步复位同步释放

4功能验证（Verification）

  • UVM 环境：Sequence 激励 + Reference Model + Scoreboard
  • 覆盖率驱动：代码覆盖率、功能覆盖率（Covergroup）、断言 SVA
  • 静态检查：Lint、CDC / RDC 检查
  • 形式验证：Formal Property Verification

5FPGA 原型验证

映射到 FPGA 跑真实软件 / 驱动，进行软硬件协同验证，提前暴露系统级问题。

第二章　逻辑综合与 DFT

6逻辑综合（Synthesis）

RTL + 标准单元库 + 约束（SDC）→ 门级网表，做时序、面积、功耗的初步优化。
输入：RTL、.lib、SDC　|　输出：门级网表
工具：Design Compiler、Genus

7DFT（可测性设计）

  • 插入 Scan Chain（扫描链）
  • JTAG / TAP 控制器
  • MBIST（存储器自测）
  • 测试压缩（Compression）降低测试成本
  • ATPG 生成测试向量，保证故障覆盖率

8形式等价性检查（LEC）

确认门级网表与 RTL 功能等价。
工具：Formality、Conformal LEC

第三章　后端物理实现

9Floorplan（布局规划）

  • 确定 Die 尺寸、IO / Pad 环

  • 电源规划 Power Plan：Ring、Stripe、Via
  • Blockage、Placement Halo 设置

标准单元摆放；Congestion 优化、Scan Reorder、Useful Skew 准备。

Global Route → Track Assign → Detail Route。
  • DRC 修复
  • 天线效应（Antenna）处理
  • 信号完整性 SI（Crosstalk）优化
  • Via 优化、冗余 Via 插入

签核项内容

可靠性ESD、Latch-up

第四章　流片与量产

14Tape-out（流片）

生成 GDSII 交付 Foundry，进行 Mask 制作与 OPC 处理。

15制造与封装

晶圆制造 → CP 测试（Wafer Sort）→ 切割 → 封装 → FT 终测。

16硅后验证（Post-Silicon Bring-up）

实测功能、时序、功耗并与仿真结果对比；若存在 Bug，可能需要 Metal ECO 或重新流片。
关键循环：每个阶段都可能因时序 / 功耗 / 面积不收敛而回退——后端 Timing 不过时甚至需要修改 RTL，这就是业界常说的 ECO 与迭代。

第五章　专题：PR 是哪个阶段

PR = Place & Route（布局布线），属于后端物理实现阶段，对应上文第 9～12 步。
子步骤内容
FloorplanDie 尺寸、宏单元摆放、电源规划
Placement标准单元布局、Congestion 优化
CTS时钟树综合、Skew 平衡
Routing全局布线 + 详细布线、DRC 修复
流程位置：Synthesis → PR → Signoff（STA / DRC / LVS）→ Tape-out
输入：门级网表（.v）、SDC 约束、标准单元库（.lib / .lef）、工艺文件（tech LEF / ITF）

业界常把 PnR 与 PR 混用，含义相同。另外 PR 在 Git 语境中指 Pull Request，需看上下文区分。

第六章　专题：PR 带反标吗

结论：PR 本身不叫"反标"，但 PR 过程中一直在使用寄生参数；真正的"反标"发生在 Signoff STA 与 后仿真 环节。

6.1反标的定义

反标（Back-annotation）：把物理实现得到的真实延迟 / 寄生信息，回标到网表或时序分析中，替代此前的估算值。

6.2各阶段互连延迟来源

阶段互连延迟来源是否反标
综合 SynthesisWire Load Model（统计估算）✗ 无
Placement 前Virtual Route 估算✗ 近似
Placement / CTS 后基于实际位置的 Steiner 树估算△ 半真实
Route 后真实 RC 提取 → SPEF✓ 真正反标
Innovus / ICC2 在 Route 后会调用寄生提取引擎（如 QRC），把真实 RC 加载进时序引擎——这属于工具内部闭环，一般不称作"反标"。

6.3场景一：Signoff STA

PR 输出 netlist + SPEF，交给 PrimeTime 做签核。
read_verilog  post_route.v
read_parasitics -format spef  top.spef   ;# 这就是反标
update_timing

6.4场景二：后仿真（Post-layout Gate-level Sim）

PR 后网表 + SDF 反标到仿真器。
initial $sdf_annotate("top.sdf", top_inst, , , "MAXIMUM");

6.5小结

文件内容用途
SPEF寄生参数 R / CSignoff STA 反标
SDF单元延迟 + 互连延迟门级后仿真反标
一句话：PR 是产生反标数据的阶段，反标动作本身发生在 Signoff STA 与后仿真。

第七章　专题：DFT 插入层次（Scan vs MBIST）

结论：
· Scan：链的物理实现必须在网表；RTL 只能做可测性准备（DFT hooks + DFT-friendly 编码）
· MBIST：控制器本身就是 RTL，主流在综合前插入，随功能逻辑一起综合

7.1Scan 为什么必须基于网表

原因说明
需要替换库单元DFF → SDFF（带 SI / SE 端口），属库单元级操作，RTL 中没有"单元"概念
需要知道全部触发器RTL 的 always @(posedge clk) 综合后到底成几个 flop、是否被优化掉，综合前无法确定
链序与物理相关Stitching 后还要在 PR 阶段做 Scan Reorder，按实际摆放位置重排以减少布线
ATPG 工作在网表故障模型（stuck-at / transition）基于门级，必须有网表
两种"看起来像 RTL"的情况：
① One-pass test-ready synthesis（DC / Genus）
输入是 RTL，但 scan 替换 / 缝合仍发生在综合产生网表之后。 
set_scan_configuration -style multiplexed_flip_flop
set_dft_signal -view existing_dff -type ScanClock -port clk
compile_ultra -scan          ;# 综合时直接用 scan flop
insert_dft                   ;# 仍然是在网表上 stitch
② RTL 里手写的 DFT 钩子（这部分确实在 RTL，称为 DFT-ready RTL / DFT hooks，不是 scan insertion 本身） 
// 测试时钟选择
assign clk_int   = scan_mode ? scan_clk   : func_clk;

// 异步复位旁路，保证 scan shift 期间复位可控
assign rst_n_int = scan_mode ? scan_rst_n : func_rst_n;

// 时钟门控在测试模式下强制打开
assign gate_en   = test_en | func_en;

7.2MBIST 典型在 RTL 阶段插入

MBIST 的主体是一个控制器 FSM，工具（Tessent MBIST、TestMAX MBIST、SMS）会直接生成 RTL。 
memory 列表 + 算法配置
        ↓
生成 MBIST Controller RTL (.v) + 接口 wrapper
        ↓
与功能 RTL 一起送入综合
        ↓
正常跑 PR / STA（MBIST 路径也要时序收敛）
放在 RTL 的好处：
  • 控制器是时序逻辑，必须经过综合优化与时序收敛
  • 可在 RTL 仿真阶段就验证 BIST 流程（跑 March 算法、注入故障验证可检测性）
  • BISR / BIRA（修复寄存器链）、ECC 也都是 RTL
MBIST 控制器自身的触发器，之后同样会被 Scan 插入覆盖（在网表阶段），两者不冲突。

7.3各 DFT 结构插入层次对照

DFT 结构插入层次说明
DFT hooks（clk mux / rst bypass / test_en）RTL手写，保证可控性
JTAG TAP 控制器RTL标准 RTL IP，需综合与时序收敛
MBIST 控制器 + wrapper + BISRRTL（也可网表）主流在 RTL
Boundary Scan（BSD）RTL 或网表看流程，常在网表插 IO cell 链
Scan 替换 + Stitching网表必须
Scan Compression（DFTMAX / TestKompress）网表与 scan 链一起插
OCC（On-Chip Clock Controller）网表（或 RTL 预置）配合 at-speed 测试
Test Point Insertion网表（部分工具支持 RTL 分析）提升覆盖率
Scan ReorderPR 阶段基于物理位置重排

第八章　专题：Scan 原理与完整流程

8.1为什么需要 Scan

问题的本质：可控性与可观测性
芯片制造后可能存在物理缺陷（断线、短路、晶体管失效）。要测出来，必须：
  • 可控性（Controllability）：能把任意内部节点设成 0 或 1
  • 可观测性（Observability）：能把任意内部节点的值传到输出端口
纯组合电路很容易做到——直接从 PI 加激励、从 PO 看结果。但时序电路里有成千上万个触发器，它们的值只能靠时钟一拍拍推进，从外部几乎无法直接控制 / 观测。
Scan 的核心思想：把所有触发器串成一条移位寄存器链，让触发器既能当"功能寄存器"，又能当"测试端口的延伸"。
于是时序电路被"降维"成组合电路测试问题：
· 触发器 Q 输出 → 组合逻辑的伪主输入 PPI（Pseudo Primary Input）
· 触发器 D 输入 → 组合逻辑的伪主输出 PPO（Pseudo Primary Output）

8.2Scan Flop 的结构

Mux-D Scan（最主流）：把普通 DFF 换成 SDFF，在 D 端前加一个二选一 MUX。 
         ┌─────────────────────────┐
  D ────▶│0                        │
         │  MUX ──▶ D   ┌─────┐    │
 SI ────▶│1             │ DFF │──▶ Q
         │              └──▲──┘    │
 SE ────▶│sel              │       │
         └─────────────────┼───────┘
  CLK ─────────────────────
SE数据来源模式
0D（功能逻辑）Functional / Capture
1SI（上一级 Q）Shift（移位）
代价：
  • 面积：每个 flop 增加一个 MUX，约 +10%~20% flop 面积
  • 时序：功能路径上多一级 MUX 延迟（约 1 级门延迟）
  • 布线：多出 scan 链的连线
Scan 风格特点
Mux-D Scan最常用，兼容性最好
Clocked Scan用两个独立时钟（功能 / 移位）切换，无 MUX 延迟但时钟复杂
LSSD（Level-Sensitive Scan Design）IBM 风格，锁存器 + 多相时钟，对时钟 skew 不敏感
链的连接：所有 flop 的 SE 并联到同一 scan_enable 端口，CLK 并联到 scan clock。
scan_in ──▶ FF0.SI
            FF0.Q ──▶ FF1.SI
                      FF1.Q ──▶ FF2.SI
                                ...
                                FFn.Q ──▶ scan_out

8.3基本操作：Shift 与 Capture

Stuck-at 测试（静态故障，三步法）
      ┌── Shift In (n cycles) ──┐  Capture  ┌── Shift Out (n cycles) ──┐
SE   ─┘▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔└___________┘▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔
CLK  ─┘│_│▔│_│▔│_│▔│_│▔│_│▔│___│▔│_________│▔│_│▔│_│▔│_│▔│_│▔│_│▔│
步骤SE动作
1 Shift In1连打 n 个时钟，把 ATPG 向量从 scan_in 串行移进所有 flop，即 PPI 激励
2 Capture0打一个时钟，组合逻辑结果（PPO）被捕获回 flop；同时 PI 加激励、PO 观测
3 Shift Out1再打 n 个时钟，把结果串行移出到 scan_out，与期望值（Golden）比对
技巧：下一个向量的 Shift In 与当前向量的 Shift Out 可重叠进行，测试时间约为 向量数 × 链长 而非 2 倍。
At-Speed 测试（动态故障）
Stuck-at 只能查"卡死"，查不出"走得慢"（transition / path delay fault），需要在功能频率下打两拍 capture。 
// Launch-On-Capture（LOC，Broadside）
Shift(慢) → SE=0 → Capture1(慢, launch) → Capture2(快, capture) → Shift(慢)
                     ↑ 发起跳变              ↑ 必须在功能周期内到达

// Launch-On-Shift（LOS，Skewed Load）
Shift(慢) ... 最后一拍 shift 用来 launch → SE 快速翻转 → Capture(快)
LOS 覆盖率高、向量少，但要求 scan_enable 能在功能频率下切换，对 SE 时序要求极高（常需为 SE 单独做类似时钟树的平衡）。
OCC（On-Chip Clock Controller）：at-speed 的快时钟由片上 PLL 提供，OCC 精确挑出需要的若干个快时钟脉冲。 
慢速 shift clock ──┐
                   OCC ──▶ 到 scan flop
PLL 快时钟 ────────┘
       ▲
   TAP 配置脉冲数量

8.4故障模型与 ATPG

故障模型描述用途
Stuck-at（SA0/SA1）节点永久为 0 或 1基础，覆盖率通常要求 >99%
Transition（TDF）跳变太慢（slow-to-rise / slow-to-fall）at-speed，查延迟缺陷
Path Delay指定关键路径总延迟超标针对关键路径
Bridging两条线短路先进工艺重要
IDDQ静态电流异常查漏电缺陷
Cell-aware基于单元内部晶体管级缺陷7nm 以下必备
ATPG 原理（Automatic Test Pattern Generation，核心算法 D 算法 / PODEM / FAN）
  • 故障激活（Activation）：在故障点制造与故障值相反的值（测 SA0 就让它为 1）
  • 故障传播（Propagation）：沿敏化路径把差异（D 值）推到某个 PO 或 PPO
  • 回溯赋值（Justification）：反推需要哪些 PI / PPI 的值才能满足上述条件
  • 故障仿真（Fault Simulation）：计算该向量顺带检出了哪些其他故障，做故障塌缩与向量压缩
Test Coverage  = 已检测故障数 / (总故障数 - 不可测故障数)
Fault Coverage = 已检测故障数 / 总故障数
常见 ATPG untestable 原因：冗余逻辑、常量绑定、不受控的时钟 / 复位、黑盒周边、组合环路。

8.5Scan Compression（测试压缩）

为什么要压缩：假设 100 万 flop、10 条链 → 每条链 10 万位；10000 个向量 → 测试数据量和 ATE 占用时间都爆炸。 
 少量外部                        大量内部短链
 scan 通道                     ┌──▶ chain 1  ──┐
   (如 10)                     ├──▶ chain 2  ──┤     (如 2000 条)
      │       ┌────────────┐   ├──▶ chain 3  ──┤   ┌──────────────┐
      └──────▶│Decompressor│──┤      ...      ├──▶│   Compactor  │──▶ 10 bit out
              │  (LFSR /   │   └──▶ chain N ──┘   │ (XOR tree /  │
              │  spreader) │                      │    MISR)     │
              └────────────┘                      └──────────────┘
  • Decompressor：利用 ATPG 向量中大量 don't care（X） 的特性，用少量输入位展开出大量内部链的激励
  • Compactor：XOR 树把大量链输出压成少量位
代价 / 难点：
  • X-blocking / X-bounding：未知值 X 经过 XOR 压缩器会污染整个输出，必须屏蔽（黑盒输出、未初始化 RAM、异步路径）
  • Masking 逻辑：用于屏蔽特定链以定位失效
  • 压缩比典型 50×~400×
工具：Synopsys DFTMAX / DFTMAX Ultra、Mentor TestKompress、Cadence Modus
LBIST（Logic BIST）：片上自带 LFSR 生成伪随机向量 + MISR 压缩响应，不依赖 ATE。
  • 优点：可做在线 / 上电自测，车规 ISO 26262 常要求
  • 缺点：伪随机向量覆盖率低，需插入 Test Point 提升；X 必须彻底清除

8.6完整 Scan 实现流程

① RTL 阶段：DFT-Ready 设计
// ① 时钟必须在测试模式可控（不能用内部分频/门控的不可控时钟）
assign clk_int   = scan_mode ? scan_clk   : div_clk;

// ② 异步复位必须在 shift 期间可控（否则 shift 中被误复位）
assign rst_n_int = scan_mode ? scan_rst_n : func_rst_n;

8.9Scan 时钟与功能时钟是否相同

维度是否相同
物理路径 / 时钟树✓ 同一棵时钟树（CTS 只建一次，scan 复用）
时钟源（根）✗ 通常不同，测试时从外部 pin 或 OCC 引入
频率✗ Shift 慢（10~50MHz），Capture 按模式分
分组 / 域划分✗ 测试时可能合并或独立控制
关键点：Scan 用的是同一条物理时钟路径（必须如此，否则测不到真实时钟树上的缺陷），但时钟源和频率不同。
① 时钟源为什么要换
功能时钟常来自 PLL、内部分频器、时钟门控，这些在测试时不可控（PLL 需锁定时间、分频器状态未知），所以要加 test clock mux。 
// 典型做法：测试模式从外部 pin 直接灌时钟
assign clk_core = test_mode ? scan_clk_pin : pll_div_clk;
对应 DFT DRC 规则 D1（Uncontrollable clock）——不加这个 mux 就会报违例，覆盖率上不去。
模式时钟来源频率
Shift外部 ATE pin低速，10~50MHz
Slow-speed Capture外部 ATE pin低速
At-speed Capture片上 PLL（经 OCC 挑脉冲）功能频率
② 频率为什么不同 —— Shift 必须慢
① ATE 通道驱动能力 / 精度有限，高速 shift 成本极高
② Shift 时所有 flop 同时翻转 → 瞬时功耗（IR-Drop）远超功能模式
③ 跨时钟域混链时，shift 路径的 skew 难以保证
④ Shift 路径是 Q→SI，通常无逻辑，慢速完全够用
Capture 分两种
// Slow-speed Capture（Stuck-at）—— 慢速即可，只查"卡死"
Shift(10MHz) → SE=0 → Capture(10MHz) → Shift(10MHz)

// At-speed Capture（Transition / Path Delay）
Shift(10MHz) ... → launch ─┐
                           ├─ 这两拍间隔 = 功能周期（如 1GHz → 1ns）
                   capture ─┘
→ 继续 Shift(10MHz)
③ OCC（On-Chip Clock Controller）
at-speed 的快时钟不可能从 ATE 给，必须用片上 PLL。 
                    ┌─────────────────────┐
 ATE slow clk ─────▶│                     │
                    │       OCC           │──▶ 时钟树 ──▶ scan flops
 PLL fast clk ─────▶│  (clock chopper)    │
                    │                     │
 scan_en ──────────▶│ 按配置挑 N 个快脉冲  │
 TAP config ───────▶│                     │
                    └─────────────────────┘
OCC 内部逻辑：shift 期间透传 ATE 慢时钟；capture 期间切到 PLL，精确放出 2~4 个快脉冲，然后再切回慢时钟。
④ 时钟树是共用的（重要）
            ┌─── CTS 建的同一棵时钟树 ───┐
clk_mux ───▶│  buf → buf → buf → flops   │
   ▲        └───────────────────────────┘
   ├── PLL clk （功能模式）
   └── ATE clk （测试模式）
为什么必须共用：
  • 时钟树上的 buffer / inverter 本身也会有缺陷，必须被测到
  • 若 scan 走独立时钟树，功能时钟树上的故障就逃逸了
  • 面积 / 功耗上也不可能建两棵树
SDC 约束写法：scan 时钟作为独立 mode 在 MMMC 中分析
# --- functional mode ---
create_clock -name func_clk -period 1.0   [get_pins pll/CLKOUT]

# --- scan shift mode ---
create_clock -name scan_clk -period 100.0 [get_ports scan_clk_pin]
set_case_analysis 1 [get_ports test_mode]
set_case_analysis 1 [get_ports scan_en]     ;# shift 模式下 SE=1

# --- scan capture mode（at-speed）---
create_clock -name scan_cap -period 1.0   [get_ports scan_clk_pin]
set_case_analysis 0 [get_ports scan_en]
这三个（甚至更多）mode 都要在 MMMC 中做 STA 签核：shift 模式一般只看 hold，capture 模式要看 setup + hold。
⑤ 多时钟域在 Scan 下怎么处理（功能上有 CLK_A / CLK_B / CLK_C 三个域）
# 不混链（主流）
chain 1,2,3  ← 全部是 CLK_A 域的 flop
chain 4,5    ← 全部是 CLK_B 域的 flop
chain 6      ← 全部是 CLK_C 域的 flop

set_scan_configuration -clock_mixing no_mix   # 链长会不均衡，但安全
Shift 时各链独立、互不影响，CLK_A/B/C 可以并行打，测试时间不叠加。

Capture 时的问题：CLK_A 域 flop 输出经组合逻辑到 CLK_B 域 flop，capture 时两个时钟同时打，域间路径时序无法保证 → 可能误报。
解决方案说明
One-hot capture每个 pattern 只打一个时钟域，域间故障放弃
Staggered capture各域时钟错开（skew 足够大），域间路径按 shift 慢速算
跨域路径 masking把域间接收 flop 设为 X / 不观测
Simultaneous capture要求 STA 保证域间时序，覆盖率最高但风险大
真正的异步跨时钟域（CDC）路径，ATPG 必须 mask 掉，否则会有随机 mismatch。
⑥ Scan 时钟相关的常见坑
坑现象对策
时钟门控（ICG）没打开下游 flop 全测不到，覆盖率骤降ICG 的 EN 或上 test_en
分频时钟驱动 flopD1 违例，这些 flop 不进链加 test clock mux 或用 OCC
Shift 时 skew 过大相邻 flop 串数据错位（shift 链 hold 违例）shift 模式单独做 hold fix
异步复位没 bypassShift 中间被复位清掉加 reset bypass mux（D5）
OCC 脉冲数配错at-speed pattern 全 fail核对 TAP 配置与 ATPG 设置一致
Shift 功耗过大IR-Drop 导致误 fail降低 shift 频率、低功耗 ATPG（减少翻转）
负沿 flop 混进正沿链shift 数据乱分链或在链中正确排序（正沿在前）
一句话总结：Scan 与功能逻辑共用同一棵时钟树（物理路径相同），但测试时时钟源切到 ATE pin 或 OCC，shift 用低速、at-speed capture 用 PLL 全速——即路径相同，源和频率不同。

8.10Scan 有几种测试模式

"测试模式"在 Scan 语境下有三个不同维度，容易混淆，需分开理解。

维度一：电路工作模式（由控制信号决定）

模式test_modescan_en时钟行为
Functional（功能）00PLL 功能时钟正常工作，scan 逻辑完全旁路
Shift（移位）11ATE 慢时钟flop 串成移位寄存器，载入 / 移出数据
Capture（捕获）10ATE 慢 或 PLL 快组合逻辑结果被采样回 flop
     test_mode=1
         │
         ├─ scan_en=1 ──▶ Shift   （D 端选 SI）
         └─ scan_en=0 ──▶ Capture （D 端选功能逻辑）
Capture 与 Functional 虽然都是 scan_en=0、都走功能逻辑，但 Capture 下时钟源仍是测试时钟、只打固定几拍；Functional 是连续运行。

维度二：测试类型 / Pattern 种类（最常说的"测试模式"）

① Chain Test（链完整性测试） —— 最先跑，也最重要 
向 scan_in 灌入 0011 重复序列 → 全程 SE=1，不做 capture
                              → 从 scan_out 比对移出的数据
  • 目的：验证 scan 链本身是通的（没断、没短路、SE / CLK 接对了）
  • 特点：不经过任何组合逻辑，只测链上的 flop 和链连线
  • 意义：链不通 → 后面所有 pattern 全废；量产中 chain test fail 直接判死
  • 典型激励 0011 0011...（可同时检测 stuck-at 0/1 与相邻短路）
  • 也叫 Flush Test（灌 0000 或 1111，检查能否透传）
② Stuck-at Test（静态故障）
项内容
故障模型SA0 / SA1，节点永久卡在 0 或 1
时序Shift 慢 → 1 拍 capture（慢速）→ Shift 慢
查什么开路、短路、晶体管完全失效
覆盖率目标> 99%
向量量相对少
Shift In(n) → SE=0 → Capture ×1 → SE=1 → Shift Out(n)
                      ↑ 慢速时钟即可
③ Transition Delay Test（TDF，跳变延迟）
项内容
故障模型slow-to-rise / slow-to-fall，跳变太慢
时序2 拍 at-speed capture（launch + capture）
查什么制造偏差导致的速度不足、电阻型缺陷
覆盖率目标85%~95%
向量量约为 stuck-at 的 2~4 倍
// ① LOC (Launch-On-Capture / Broadside)
Shift(慢) → SE=0 → launch拍(慢) → capture拍(快) → Shift(慢)
                    ↑ 用功能逻辑产生跳变
优点：对 SE 时序无要求
缺点：launch 的值受组合逻辑约束，覆盖率偏低、向量多

// ② LOS (Launch-On-Shift / Skewed Load)
Shift(慢)... → 最后一拍shift当launch → SE快速翻转 → capture拍(快)
                                         ↑ 这里最难
优点：launch 值完全可控，覆盖率高、向量少
缺点：SE 必须在功能频率下切换 → SE 要做类时钟树的平衡
④ Path Delay Test（路径延迟）
项内容
故障模型指定的某条完整路径总延迟超标
输入需从 STA 导出关键路径列表（如 top 1000 条）
特点针对性强，向量少，但需手工指定路径
用途高频设计验证关键路径是否真的够快
⑤ IDDQ Test
把芯片置于静态（时钟停止）→ 测静态电源电流
正常：漏电流极小
异常：电流偏大 → 存在桥接 / 漏电缺陷
不需要 capture，只需 shift 进一个状态然后停钟测电流。先进工艺下漏电本来就大，IDDQ 区分度下降，用得少了。
⑥ Bridging / Cell-aware Test（在 stuck-at + TDF 之上的补充 pattern，提升 DPPM）
模型说明
Bridging两条相邻线短路（需要布线后的物理邻接信息）
Cell-aware基于标准单元内部晶体管级缺陷库（厂商提供），7nm 以下必备
Gate-exhaustive对每个门穷举所有输入组合

维度三：测试访问架构模式（由 TAP / 配置寄存器切换）

① Bypass / Serial Mode（直通模式）
ATE pin ──────────────▶ 少量长链 ──────────────▶ ATE pin
         （不经过 decompressor / compactor）
用途：chain test、失效诊断（Diagnosis）、压缩逻辑本身出问题时的 debug
特点：链很长、测试时间长，但结果一对一可追溯
② Compression Mode（压缩模式，量产主用）
10 pin ──▶ Decompressor ──▶ 2000 条短链 ──▶ Compactor ──▶ 10 pin
用途：量产测试，测试时间缩短 50×~400×
特点：输出是 XOR 混合的，单个 pattern fail 难以直接定位
③ LBIST Mode（逻辑自测）
片上 LFSR ──▶ scan 链 ──▶ MISR ──▶ 最终 signature 与期望值比对
用途：上电自测、在线周期自测（车规 ISO 26262 / 功能安全要求）
特点：不依赖 ATE，但覆盖率低（需插 Test Point）、X 必须彻底清零
④ Hierarchical / Core-based Mode
大 SoC 分 core，每个 core 独立 wrap（IEEE 1500 / 1687）
→ 可以单独测某个 core（INTEST）
→ 或测 core 之间的互连（EXTEST）

完整的量产测试流程（模式串联）

① Chain Test              ← 必须先过，链不通就 stop
② Stuck-at (压缩模式)      ← 主力，覆盖率最高
③ Transition LOC/LOS      ← at-speed，查速度缺陷
④ Path Delay              ← 关键路径补充
⑤ MBIST                   ← 存储器（独立于 scan）
⑥ IDDQ                    ← 可选
⑦ Bridging/Cell-aware     ← 先进工艺补充
   ─────────────────────
   失效片 → 切 Bypass 模式 → Diagnosis 定位

核心区别一览表

测试模式Capture 拍数时钟速度过组合逻辑主要查
Chain Test0慢✗ 不过链本身
Stuck-at1慢✓卡死型缺陷
Transition2快（capture 拍）✓速度不足
Path Delay2快✓（指定路径）关键路径延迟
IDDQ0停钟—漏电 / 桥接
LBIST多慢或快✓在线自测
一句话区分：Chain test 测"链自己"；Stuck-at 测"通不通"；Transition / Path 测"快不快"；IDDQ 测"漏不漏"。前三者都靠 Shift + Capture，区别只在 capture 几拍、拍间多快。

五、差异的物理根因

1) 漏电 ↑↑            -> IDDQ 失效，转向 Cell-aware / Vmin
2) 器件变 3D 结构      -> 缺陷不再是"节点 stuck"，而是 cell 内晶体管级异常 -> CAT
3) flop 数 ↑↑          -> pattern 量爆炸 -> 高压缩 SSN + Hierarchical DFT
4) EUV 随机缺陷        -> 需量产诊断闭环（Volume Diagnostics）做良率学习
5) 低压 + AVS          -> 每片都要 scan-based Vmin 搜索并写 eFuse
6) IR-Drop 敏感        -> Low-power ATPG 从"可选"变"必须"
7) 车规 / 数据中心需求  -> LBIST 在线自检成为强需求
一句话总结：
28nm —— Scan 找的是确定性缺陷（断路/短路/桥接），Stuck-at + TDF + IDDQ 三件套 + Flat 架构即可达标。
≤7nm —— Scan 找的是概率性 marginality（cell 内部微缺陷、小延迟缺陷）， 必须 Cell-aware + Timing-aware TDF + Hierarchical DFT + SSN 超高压缩 + Low-power ATPG + 量产诊断闭环组合才能在可接受成本下达到 DPPM 目标。

9.4时序逻辑电路的测试

核心结论：测试电路的复杂性随着寄存器级数几何倍增加。

对比项纯组合电路含 N 级寄存器的时序电路
要施加激励 直接写 PI，1 拍到位 必须经多拍时钟把值"推"进内部 FF，需要一个输入序列
要观测响应 直接看 PO 内部 FF 的值要再经多拍才能传到 PO，中途可能被掩盖
状态空间 2#PI 2#PI × 2#FF，随 FF 数指数增长
ATPG 难度 组合 ATPG，成熟高效 时序 ATPG，几乎不可用于大规模设计
覆盖率 可达 99%+ 通常只有 60%~70%，且运行时间无法接受
这正是 Scan 存在的理由：把所有 FF 改成可串行读写的 Scan Cell， 让 FF 的 Q 变成"可直接写入的伪输入 PPI"、D 变成"可直接读出的伪输出 PPO"， 于是时序 ATPG 问题被降维成组合 ATPG 问题。

9.5Muxed-D Scan Cell

  • 3 个 input，1 个 output，1 个 clock pin
  • Scan Enable（SE） 引脚负责选择数据来源：
    • SE = 1 → shift mode，数据通路为 SI → Q
    • SE = 0 → capture mode，数据通路为 DI → Q
引脚方向作用
DIinput功能数据输入（原 DFF 的 D），来自组合逻辑
SIinput扫描数据输入，接上一级 scan cell 的 SO
SEinput扫描使能，选择 MUX 通路（全局广播信号）
CLKclock时钟（功能与扫描共用同一棵时钟树）
Qoutput既是功能输出 DO，也是扫描输出 SO（同一根线）
SE 值模式数据通路用途
SE = 1 shift mode SI → Q 把测试激励串行移入链中 / 把捕获结果串行移出
SE = 0 capture mode
（= 功能模式）		 DI → Q 打一拍功能时钟，让组合逻辑的响应被寄存下来 
// Muxed-D scan cell 行为模型
wire d_int = se ? si : di;      // SE=1 走扫描，SE=0 走功能

always @(posedge clk or negedge clr_n)
  if (!clr_n) q <= 1'b0;
  else        q <= d_int;
代价：每个 flop 多一级 MUX —— 面积增加约 10%~20%（flop 部分）， 功能路径上多出 1 级 MUX 延迟。
收益：所有 flop 的 Q 可任意写入（可控性）、D 可任意读出（可观测性）， ATPG 覆盖率从 60%~70% 提升到 99%+。

9.6Pre-scan Design → Post-scan Design

课件用同一个电路（3 个 PI、2 个 PO、3 个 FF）展示了 scan 插入前后的变化。 完整 SVG 结构图见前文 图 8.11-0，此处汇总讲义要点。

阶段讲义原文要点
pre-scan design Non-scan cell —— FF₁/FF₂/FF₃ 为普通 D 触发器，只有 D / Q / CK
post-scan design Non-scan cell 替换为 scan cell（SFF₁/SFF₂/SFF₃）
Extra pins：SI、SE、SO
提高可控性和可观测性：串成 scan chain 
# 以讲义中 3 入 2 出 3 FF 的例子为例

pre-scan ：  PI = X1,X2,X3            PO = Y1,Y2
             （FF 的 D/Q 完全不可直接访问）

post-scan：  PI  = X1,X2,X3   +  PPI = SFF1.Q, SFF2.Q, SFF3.Q
             PO  = Y1,Y2      +  PPO = SFF1.DI, SFF2.DI, SFF3.DI

             3 入 2 出  →  6 入 5 出

关键转换：FF 的 Q 升级为 PPI（Pseudo Primary Input，等效额外输入脚）， FF 的 D 升级为 PPO（Pseudo Primary Output，等效额外输出脚）。
加上 SE 全局广播、SI/SO 首尾串联，组合逻辑的每个输入都可控、每个输出都可观测， 9.4 节说的"复杂度几何倍增加"问题随之消失。

9.7Scan Test 过程总览

一个完整的 scan 测试由四个阶段组成：

阶段SE做什么
Test Setup—上电、解锁、释放复位、配置时钟、进入 scan mode（SC_Mode=1）
LoadSE=1脉冲 SC_CLK，把 ATE 上的测试激励经 scan chain 移入 scan cell
CaptureSE=0Force PI / Measure PO，打一拍 SC_CLK 捕获组合逻辑响应
UnloadSE=1把捕获值移出到 SCO 与期望值比对；同时移入下一个 pattern
看波形的三个关键点：
① SE 在 Load / Unload 期间为高，Capture 期间拉低 —— 它是区分三个阶段的唯一标志；
② SC_CLK 在 Load / Unload 期间是连续的 shift 脉冲串，Capture 期间只有 1 个脉冲（stuck-at）；
③ Unload 与下一 pattern 的 Load 重叠（图中 Unload 段 SCI 仍在送 0,1,1,1,0）—— 这是测试时间只按"向量数 × 链长"而不是"×2"计算的原因。

9.8Test Setup

  • Power up、security unlock、reset release、clock configuration、scan mode entry
  • SC_Mode = 1
动作目的
Power up各电源域按时序上电，确保所有 power domain 处于 on 状态（测试时一般不关电）
Security unlock解除芯片的测试访问保护（防止量产后被人通过 scan 链读出密钥）
Reset release释放异步复位，否则所有 flop 被钳住，DFT DRC D5 违例，根本无法移位
Clock configuration把 PLL/分频器配置到测试所需状态；shift 时钟切到 ATE 直供或 OCC bypass
Scan mode entry拉高 SC_Mode，打开所有 DFT hook：clk mux 切测试钟、ICG 强制透传、异步 rst bypass、黑盒隔离
SC_Mode 与 SE 的区别（容易混）：
SC_Mode（也叫 test_mode）—— 整段测试期间一直为 1，是"静态"配置信号，管的是"芯片处于测试态"。
SE（Scan Enable）—— 在 Load/Capture/Unload 之间来回翻转，是"动态"控制信号，管的是"此刻走扫描路径还是功能路径"。

9.9Load（移入激励）

  • Pulse SC_CLK，SE = 1
  • 将 ATE 上的测试激励通过 scan chain 加载至 scan cell
要素说明
SE = 1所有 scan cell 的 MUX 切到 SI，组合逻辑的输出被旁路，整条链变成移位寄存器
Pulse SC_CLK每来一个时钟沿，数据向后推一级。需要 N 拍（N = 最长链长度）才能灌满
数据来源ATE 的 pattern memory，经 SCI 引脚串行送入
此时 PI/PO不关心（图中 PI 为 don't care），组合逻辑输出无意义
结果每个 scan cell 的 Q 被设成 ATPG 指定的值 → PPI 完成赋值

9.10Capture（捕获响应）

  • SE = 0
  • Force PI & Measure PO
  • Pulse SC_CLK，捕获组合逻辑的响应值至 scan cell
动作作用
SE = 0 MUX 切回 DI，scan cell 回到功能模式，组合逻辑的输出重新连通到 flop 的 D
Force PI ATE 在真实输入脚上施加激励 —— 与 Load 进去的 PPI 一起，构成完整的组合逻辑输入向量
Measure PO 在打 capture 时钟之前先比对真实输出脚 —— 这部分响应不经过 flop，直接可观测
Pulse SC_CLK（1 拍） 把组合逻辑的响应（即 PPO）锁存进 scan cell，等待 Unload 移出比对 
# 一个 pattern 的完整响应观测分两路

  PO  路径：组合逻辑 -> 输出 pad        -> Measure PO    （capture 时钟前比对）
  PPO 路径：组合逻辑 -> scan cell 的 DI -> capture 锁存 -> Unload 移出比对

# 时序顺序（一个 capture cycle 内）
  force PI  ->  measure PO  ->  pulse SC_CLK  ->  PPO 入锁
为什么 Capture 只打 1 拍？
因为 Scan 的目的就是把问题降维成组合电路测试： PPI（Load 进去的值）+ PI（Force 的值）= 组合逻辑的完整输入， 打 1 拍就能把组合逻辑的全部响应抓到 PPO 和 PO 上。
打多拍反而会让响应再次经过组合逻辑被覆盖，重新退化成"难测的时序问题"。
例外：Transition（at-speed）测试需要 2 拍（launch + capture），即 LOC 方式。

9.11Unload（移出响应）

  • Pulse SC_CLK，SE = 1
  • Scan cell 已经捕获到的值，将其通过 scan chain 输出，实现观测
动作作用
SE = 1MUX 再次切到 SI，scan chain 重新连通成移位寄存器
Pulse SC_CLK（N 拍）把每个 scan cell 捕获到的 PPO 依次推向 SCO
ATE 在 SCO 比对每拍与期望值（good machine 仿真值）比较，不一致 → Fail，记录 cycle 与 chain 位置供 diagnosis
SCI 同时在动波形中 Unload 段 SCI 又出现 0 1 1 1 0 —— 这是下一个 pattern 的 Load
Unload 与下一个 Load 是重叠（overlap）的。
一条长度为 N 的链，移出当前响应要 N 拍，移入下一激励也要 N 拍。 由于两者都只是"移位"，ATE 在同一段 N 拍里从 SCI 灌新激励、同时从 SCO 收旧响应， 把 2N 拍省成 N 拍。
这就是为什么整个 scan 测试时间近似为： Total cycles ≈ (Pattern 数 + 1) × 链长， 而不是 2 × Pattern 数 × 链长。
也正因如此，缩短最长链的长度（即增加链数 / 用 compression）是降低测试时间最直接的手段。 
# 一个 pattern 的完整时序（稳态流水）

  Test Setup  ->  Load(N)  ->  Capture(1)  ->  Unload(N) / Load_next(N)  ->  Capture(1) -> ...
                  ^                             ^^^^^^^^^^^^^^^^^^^^^^^
                  只在第一个 pattern 单独做      之后每个 pattern 的移出与移入合并

2 test pattern generation ATPG 跑 stuck-at / transition / 其它故障模型，做 DRC 检查、coverage 收敛、pattern count 优化，输出 STIL/WGL 与覆盖率报告
3 test pattern simulation 把 pattern 回灌到门级网表做仿真（zero-delay + SDF 后仿），确认无 X、无 mismatch、at-speed 时序合法
4 test pattern release 转换为 ATE 可用格式，连同 timing（tester timing set）、pin map、电压/频率条件交付测试工程团队
5 silicon bring up and diagnosis 硅片回来上机台调试：yield 分析、failing pattern 定位、scan chain diagnosis 回推到具体 cell/net，反馈给设计或工艺
这 5 步覆盖了"前期插入 → 中期验证 → 后期硅上闭环"的完整链路。 其中第 1～2 步是产出物的核心，第 3 步是质量闸门（pattern 不过仿真绝不能上机台）， 第 5 步决定了前面工作做得好不好 —— 能不能定位到失效点，取决于 scan 架构和 diagnosis 能力是否在第 1 步就设计好了。

9.13Scan 架构介绍：四种常见扫描测试架构

架构 实现方向 核心优势 特征
Fast scan top down / bottom up Low cost 不加压缩，chain 直接接到 PAD。结构最简单、EDA license 与人力成本最低，但链长、测试时间长
Partition ATPG bottom up Least run time & complexity 按 partition 分块跑 ATPG，单次跑的设计规模小，工具运行时间短、调试复杂度低
Full Chip ATPG top down / bottom up Shortest test time 全芯片一次打平跑 ATPG，pattern 可跨模块共享压缩，pattern 数最少 → 机台时间最短，但工具内存/runtime 压力极大
Hierarchical ATPG bottom up Modular reuse capability core 级生成 pattern 后在 top 级 retarget（配 wrapper / IJTAG），IP 可复用、支持并行开发，大型 SoC 主流方案

9.14如何选择适合项目的扫描测试架构

测试架构：没有最好，只有最适合。
通常需要权衡 cost / schedule / complexity / resource / test quality。
权衡维度含义
costATE 机台时间、EDA license、封装/探针资源折算的量产成本
scheduleDFT 插入与 ATPG 收敛是否卡住 tape-out 时间表
complexity架构越复杂（compression / hierarchical / SSN），调试与 bring-up 风险越高
resource人力、服务器算力/内存、可分配的测试管脚数
test quality覆盖率与 DPPM 指标 —— 消费级与车规级要求差一个数量级

选择架构时要看的四个实际约束：

约束如何影响架构选择
项目的大小 <20K ffs → Fast Scan 足够；百万级 ffs → 必须 compression；千万级 → 必须 Hierarchical
管脚数量 可用测试管脚少 → 链数受限 → 链变长 → 必须上压缩；管脚充裕则可多链并行、免压缩
结构层次划分 设计是否有清晰的 core 边界、IP 是否可独立交付 → 决定能否走 bottom-up / Hierarchical
ATE 的制约 机台通道数、pattern memory 深度、最高 shift 频率、可支持的 at-speed 能力，直接限定链数与 pattern 上限

9.15Fast Scan

特点说明
极小项目（<20K ffs）触发器总数很少，即使不压缩，链长与 pattern 数也在可接受范围
管脚资源充分有足够的 PAD 直接做 SI/SO，链数可以开得多 → 单链自然就短
无需压缩不插 decompressor / compactor，省掉一整套结构与对应的 DRC、X-masking 麻烦
复杂度低网表干净、ATPG setup 简单、后端 SCANDEF reorder 也容易
易于诊断SCO 上每一拍对应链上唯一一个 scan cell，failing bit → cell 是一一映射，不像压缩后需要反解 compactor
Fast Scan 的代价：所有 flop 的数据都要原封不动地经 PAD 串进串出， 一旦规模上到百万级 flop，链长和 pattern 数会让 ATE 时间（= 成本）不可接受。
所以它的定位很明确 —— 小型 IP、小芯片、或作为大芯片初期的 bring-up / debug 模式（压缩模式出问题时退回 bypass 链调试）。

9.16Full Chip ATPG（Top-Down）

特点说明
较小项目（< 100K ffs）规模可控，工具能一次性打平装下整个设计
层次划分较少设计本身没有清晰可独立交付的 core 边界，或者没必要分
整体综合全芯片一起综合、一起插 DFT，EDT codec 只在 top 做一套
复杂度低不需要 wrapper、不需要 pattern retarget，流程线性简单
测试时间少全局 ATPG 可以让不同 core 的故障在同一个 pattern 里被同时检测 → pattern 数最少
Top-Down 的本质：DFT 只在最顶层做一次。好处是 pattern 压缩效率最高（全局共享 channel）， 代价是必须等所有 core 的网表齐了才能开工 —— 一旦 RTL 有改动，整条 DFT + ATPG 流程要从头再跑。

9.17Full Chip ATPG（Bottom-Up）

特点说明
中小项目（< 2M ffs）规模已超出 Top-Down 承受范围，但还没到必须切 partition 的程度
按照项目层次划分 EDT以 core 为单位各插一套 decompressor + compactor
各个模块独立综合core 可以并行开发、独立做 DFT 插入和时序收敛
早期得到各模块的测试数据某个 core 先完成就能先跑 ATPG 看覆盖率，问题早暴露，不用等全芯片
复杂度中比 Top-Down 多了 core 级 EDT 的配置与顶层通道连接管理
测试时间少ATPG 仍在全芯片视角一次性生成 pattern，各 core 的 pattern 可并行加载
Top-Down vs Bottom-Up 的关键区别不在 ATPG，而在 EDT codec 放在哪一层。
Top-Down：codec 在 top，chain 跨 core → 必须等全网表。
Bottom-Up：codec 在每个 core 内 → core 可独立交付，但通道数会随 core 数增加，管脚压力变大 —— 这正是下一节 Channel Sharing 要解决的问题。

9.18Compression Channel Reuse：Share IO codec / Data Channel Sharing

# Typical：通道独占，总数 = 各块之和
  BLOCKA 20K -> 8 Channels
  BLOCKB 10K -> 4 Channels
  BLOCKC  5K -> 2 Channels
  合计 = 8 + 4 + 2 = 14 个测试管脚

# Data Channel Sharing：数据通道共用，每块只多 1 根专用选择信号
  BLOCKA -> 1 + 11 Channels
  BLOCKB -> 1 + 11 Channels   （这 11 根是同一组物理线）
  BLOCKC -> 1 + 11 Channels
  合计 = 11（共享数据）+ 3（各 1 根专用）= 14 根线，但每块可用带宽从 2~8 提升到 11
特点说明
中大项目（< 5M ffs）block 多、每块都要通道，管脚迅速不够用
缺少测试管脚时推荐使用核心价值：用同一组物理 IO 服务多个 block，靠使能信号分时/选择性激活
复杂度略高需要共享总线的仲裁/选择逻辑，DRC 与时序（长距离总线）要额外关注
测试时间最优小 block 不再被"只分到 2 根通道"卡住 —— 测它时可以用满 11 根 → 链更短、shift 拍数更少
为什么共享反而更快？
Typical 方案下，BLOCKC 只有 5K flop 却只分到 2 个通道，链被迫拉得很长； 而 BLOCKA 测完后它那 8 根通道就闲置了。
Channel Sharing 把这 14 根线变成公共资源池：测哪个 block，哪个 block 就独占 11 根 → 每个 block 的链长都被压到最短，总 shift 时间自然最优。这就是"Share IO codec"的本质。

9.19Partition ATPG（Bottom-Up）

特点说明
超大项目（> 5M ffs）打平跑 ATPG 的内存与 runtime 已经完全不可行
极缺测试管脚分 partition 后每次只测一块，同一组管脚可被所有 partition 轮流复用
Low power同时只有一个 partition 在 toggle → shift / capture 功耗大幅降低，避免 IR-Drop 误判
复杂度中需要 PCL（Pattern/Partition Control Logic）做分区使能与隔离
分而治之，降低 ATPG run time每次只装载一个 partition 的网表，工具内存占用与运行时间大幅下降
漏洞明显无法测试两个模块之间连接的故障 —— 跨 partition 的 interconnect 既不在 A 的测试范围，也不在 B 的
Partition ATPG 最大的硬伤就是最后一条。
图中 Core A 与 Core B 之间那些红色箭头代表的互连线，两端分属不同 partition： 测 A 时 B 侧的 flop 不受控、测 B 时 A 侧的 flop 不可观 → 这段逻辑的故障检不出来。
解决办法就是下一节的 Hierarchical ATPG —— 在 partition 边界加 wrapper scan chain， 让边界本身变得可控可观。

9.20Hierarchical ATPG（Bottom-Up）

特点说明
超大项目（> 5M ffs）当今大型 SoC / AI 芯片的主流选择
拥有 Partition ATPG 的所有优点管脚复用、Low power、ATPG run time 可控
Wrapper scan chain 能够对模块间的互联逻辑进行测试边界 flop 既可当 PPI 驱动对端，也可当 PPO 观测对端 → 补上 interconnect 覆盖率
模块复用core 级 pattern 可在 top 级 retarget；同一 IP 用在不同项目里 pattern 可直接复用
额外的 DRC check，复杂度大，难度高wrapper 的 inward/outward 模式、core 与 top 的时钟/复位隔离、retarget 的合法性都要逐项检查
人力要求高需要对 IEEE 1500 wrapper / IJTAG 有深入理解的资深 DFT 工程师
# Wrapper 的两种模式（IEEE 1500 核心概念）

  INWARD  facing  ：wrapper cell 向 core 内部驱动 / 观测  -> 测 core 内部逻辑
  OUTWARD facing  ：wrapper cell 向 core 外部驱动 / 观测  -> 测 core 之间的互连逻辑

# 两种模式配合 => 全芯片无盲区
  core 内部故障  -> INWARD  模式，core 级 pattern retarget 到 top
  互连线故障     -> OUTWARD 模式，top 级单独生成 interconnect pattern

五种架构横向总结

架构 适用规模 复杂度 测试时间 关键取舍
Fast Scan< 20K ffs极低长 无压缩，管脚够用才行；易诊断
Full Chip (Top-Down)< 100K ffs低少 顶层单套 EDT；必须等全网表齐
Full Chip (Bottom-Up)< 2M ffs中少 每 core 一套 EDT；可早期拿到模块数据
Channel Sharing< 5M ffs略高最优 共享 IO codec；缺管脚时的最佳解
Partition ATPG> 5M ffs中中 run time 低、低功耗；互连盲区
Hierarchical ATPG> 5M ffs高中 wrapper 补盲区 + 模块复用；人力与 DRC 代价大

本节对应 PPT 最后一页 Summary，把第九章四条主线串成一张流程图：原理 → 过程 → 工作内容 → 架构。

主线对应小节一句话抓手
Scan Test 原理9.1 ~ 9.6 时序电路直接测 = 指数级难度；插入 scan 后，所有 flop 变成可直接写（PPI）/ 可直接读（PPO）的伪 IO， 测试问题降维成纯组合电路测试，覆盖率从 60~70% 拉到 99%+
Scan Test 过程9.7 ~ 9.11 setup（进 scan mode、配时钟）→ load（SE=1 移入激励）→ capture（SE=0 打 1 拍）→ unload（SE=1 移出比对， 与下一 pattern 的 load 重叠）；总周期 ≈ (Pattern 数 + 1) × 链长
Scan 工作内容9.12 DFT 工程师日常：scan insertion → pattern generation → pattern simulation → pattern release → silicon bring-up & diagnosis（硅后失效定位回到链上某个 cell）
Scan 架构9.13 ~ 9.20 按规模 + 管脚数 + 层次划分 + ATE 能力四约束选架构：Fast Scan → Full Chip（Top-Down / Bottom-Up） → Channel Sharing → Partition → Hierarchical
关于 PPT 上那句「组合电路测试 → 时序电路测试」
字面方向容易误读。准确表述是：用「组合电路测试」这套成熟方法，去解决「时序电路测试」这个难题。 桥梁就是 scan chain —— 它把时序电路中那些深埋的触发器，变成组合逻辑边界上的可控点和可观测点。

# 为什么要 scan
  时序电路状态空间爆炸  ->  flop 不可控 / 不可观测  ->  覆盖率上不去

# scan 怎么做到
  普通 DFF  --(加 MUX)-->  Scan FF  --(串起来)-->  Scan Chain

  SE=0 : 功能模式，flop 捕获组合逻辑输出

# 一个 pattern 的生命周期
  setup --> load(N拍) --> capture(1拍) --> unload(N拍，与下个load重叠)

# 规模一大怎么办
  链太长 -> 压缩(EDT)   管脚不够 -> channel sharing
  run time 爆 -> partition   互连测不到 -> hierarchical + wrapper
