1. 什么是中断

中断（Interrupt）是硬件向处理器发起的异步通知机制：某个模块检测到需要软件介入的事件（数据到达、传输完成、错误发生、定时到期），通过一根电信号（或一条消息）告诉 CPU「停下手头的事，来处理我」。CPU 在当前指令边界保存现场，跳转到对应的中断服务程序（ISR），处理完再恢复现场继续。

从数字设计的角度看，中断就是一条从事件产生点一路传播到 CPU 的控制通路，这条通路上布满了捕获逻辑、锁存器、使能位、屏蔽位、优先级仲裁和清除逻辑。本文要讲的就是这条通路的每一个环节。

1.1 中断 vs 轮询

维度轮询 Polling中断 Interrupt
响应延迟最坏等于一个轮询周期，不确定硬件通路延迟，可做到几十 ns 级
CPU 占用空转读寄存器，浪费带宽无事件时 CPU 可执行其他任务或进低功耗
功耗差（CPU 必须保持唤醒）好（中断可作为唤醒源，见下）
实现复杂度低，只需状态寄存器高：锁存、屏蔽、优先级、清除、CDC 全都要做
适用场景事件频率极高且稳定（如满速 DMA 搬运中途）事件稀疏、突发、不可预测

实际芯片里两者并存：同一个状态寄存器既挂到中断通路上，也允许软件直接轮询。高吞吐场景常用「中断 + 批处理」或「中断聚合（interrupt coalescing）」——攒够 N 个事件或超时 T 再报一次中断，避免中断风暴把 CPU 淹掉。

2.1 按来源：内部 / 外部 / 软件 / 核间 / 消息

类别举例设计要点
片内外设中断UART RX 非空、SPI 传输完成、DMA 通道结束、Timer 溢出、ADC 转换完成与 CPU 常在同一或相关时钟域；数量最多，必须分级聚合
外部引脚中断GPIO 中断、专用 nIRQ 引脚、PMIC 告警、按键必须去抖 + 同步（见 §9）；极性可配置；常用作低功耗唤醒源
软件中断ARM GIC 的 SGI、RISC-V 的 MSIP、写 INT_FORCE 寄存器调度、任务切换、驱动自测；硬件上就是一个可写的 pending 位
核间中断 IPI多核 cache 维护、TLB shootdown、调度唤醒需要每核独立的 pending/清除通路，注意多核同时写的原子性
消息中断 MSI/MSI-XPCIe 设备通过写一个特定地址来"发中断"没有物理 IRQ 线，中断变成一次写事务；天然支持大量中断号；要注意写事务与数据的顺序性
错误 / 安全中断ECC 双比特错、总线 decode error、温度过高、电压跌落通常走 NMI 或独立高优先级通路，不可被普通屏蔽关掉
调试中断断点、watchpoint、halt 请求独立通路，优先级最高，与功能中断隔离

MSI 的经典坑：设备先写数据到内存、再写 MSI 地址发中断。如果两条写走了不同路径或被重排，CPU 进 ISR 时可能读到旧数据。解决方法是在发 MSI 前插入屏障 / 等待写完成响应，或者 ISR 里先读一次设备寄存器做"push flush"。

2.2 按可否屏蔽：可屏蔽 / 不可屏蔽

类型能否被软件关掉典型用途设计注意
可屏蔽中断 IRQ能，各级 mask / 全局开关都可关绝大多数功能中断关中断期间事件必须被锁存，不能丢
不可屏蔽中断 NMI不能（或只能在极早期配置阶段锁死）看门狗超时、致命硬件错误、掉电告警不能被 pending 排队淹没；ISR 必须极短；清除通路要独立，不能依赖被卡住的总线
快速中断 FIQ能，但有独立开关和更高优先级ARM 上的低延迟通路（有影子寄存器省去压栈）通常只分配给一个源，否则失去"快"的意义

NMI 不等于"不用清除"。NMI 同样需要清除机制，否则电平型 NMI 会导致 CPU 刚从 ISR 返回就立刻再次进入，形成死循环，连调试器都连不上。常见做法：NMI 源做成边沿捕获 + 独立 W1C，且清除寄存器挂在一条简单的、不依赖主总线的 APB 上。

2.3 按触发方式：电平 / 边沿

这是硬件设计中最关键的分类维度，直接决定捕获电路怎么写、中断会不会丢、怎么清除。这里先给结论表，详细展开见 §5～§8。

触发方式判定条件是否需要锁存清除方式
高电平触发src == 1 持续有效可不锁存（源自带保持）根因消失后自动撤销
低电平触发src == 0，多用于开漏共享 nIRQ同上同上
上升沿触发src 由 0→1 的那一拍必须锁存软件 W1C / 读清 / 自清
下降沿触发src 由 1→0 的那一拍必须锁存同上
双沿触发任意跳变必须锁存同上；常用于编码器、低功耗唤醒

好的 IP 设计会把触发方式做成每源可配置（INT_TYPE + INT_POLARITY 两个寄存器），GPIO 控制器几乎都这么做。片内外设则由设计者在 spec 中逐条明确写死，并在寄存器手册中标注——绝不能让软件去猜。

第 三 部 分

中断的层级与使能屏蔽

一颗 SoC 有几百上千个中断事件，CPU 只有几根 IRQ 线。中间必然是一棵收敛的树。树的每一层都有自己的使能位和屏蔽位——这是中断调试最容易踩坑的地方：任何一层关着，中断就上不去。

对照两张图理解中断调试：图 3-2 的 ④ 绿色锁存点，就是图 3-1 里每一个绿色叶子节点的内部展开。调试时"读 RAW 有没有"就是在探测 ④，"读 STATUS 有没有"就是在探测 ⑤ 之后。两者不一致，问题必然出在 mask；RAW 本身就没有，问题必然在 ①～③（事件没产生、同步丢了、或捕获极性配错）。

为什么每一级都要有 EN 和 mask？

  • 粒度控制：软件既要能一次性关掉整个 IP 的中断（顶层），也要能只关掉某个具体子源（叶子），而不影响同模块的其他源。
  • 分层调试：出问题时逐级读 status 就能定位"卡在哪一层"，见 §4.3 的排查表。
  • 多主控隔离：不同 CPU/不同安全域可以各自持有不同层级的开关，互不干扰。

但要牢记：闸门可以有很多层，锁存只能有一层（在叶子的 INT_RAW）。中间任何一级如果擅自加了寄存器把聚合结果锁住，就会出现"清了叶子，上层 IRQ 不撤销"的中断风暴，见 §3.3。

核心原则：锁存只做一次，屏蔽可以做多次。事件在 L0/L1 被锁存成 pending 位，往上各层只是组合与门（放行/拦截）。这样无论上层屏蔽开关怎么动，事件都不会丢——屏蔽打开后 pending 仍在，中断会立刻重新上报。

3.1 L0 源级：事件捕获与单源使能

最底层，紧贴事件产生点。职责是把物理事件变成一个干净的、同步到寄存器时钟域的、可被锁存的 1 bit。

要素说明
捕获方式电平直通 / 上升沿 / 下降沿 / 双沿，见 §5～§6
极性配置INT_POLARITY[n]，外部引脚中断必须有
去抖 / 滤波机械按键、慢速外部信号需要数字滤波计数器
同步器异步源必须两级同步后再捕获
源级使能SRC_EN[n]：关掉后连 raw 位都不置。注意这与 mask 语义不同——mask 只挡上报、raw 仍记录；src_en 关掉则事件彻底不记录

源级使能是双刃剑。它能彻底避免无用事件占用 pending（省功耗、避免风暴），但也意味着关闭期间的事件永久丢失，软件打开后无法得知期间发生过什么。设计时必须在手册中明确标注该位的语义，否则软件会误以为是普通 mask。大多数设计只保留 mask，不做 src_en，除非有明确的功耗或风暴需求。

3.2 L1 模块级：RAW / MASK / STATUS / CLEAR 四件套

这是每个 IP 内部的标准中断寄存器组，也是设计者最常亲手写的一层。一个 32 位寄存器可容纳 32 个子中断源。

寄存器访问属性含义

3.3 L2 子系统 / 聚合级

当中断数远多于控制器的输入端口时，需要把多个模块的中断或到一根线上，由软件进 ISR 后再读二级状态寄存器定位。

该层的控制位作用
SUB_EN / SUB_MASK整条聚合支路的使能/屏蔽
SUB_STATUS每 bit 对应一个下游模块，只读、不锁存（直接反映下游 int 线）

聚合层千万不要再锁存。如果这一层也做了 pending 锁存，就出现了"两处 pending"：软件清了下游模块的 raw，聚合层的 pending 还在，IRQ 线不撤销，ISR 立刻重入——这是最常见的中断风暴成因之一。聚合层必须是纯组合的 OR。

3.4 L3 控制器级：GIC / PLIC / NVIC

中断控制器负责仲裁：从几百个 pending 中选出优先级最高的一个送给 CPU，并提供分发（送给哪个核）、优先级、抢占、安全分组等能力。

4. 使能、屏蔽与状态寄存器

4.1 RAW / MASK / MASKED 三件套

这是中断寄存器设计的标准范式，ARM PrimeCell 系列（PL011 UART、PL022 SPI 等）几乎都遵循：

事件 ──▶ ┌─────────┐ ┌─────────┐ │ RAW 位 │────┬────▶│ & EN │────▶ 上报 │ (锁存) │ │ └─────────┘ └────▲────┘ │ │ │ ▼ ▼ CLR 写1清 RIS 可读 MIS 可读 (原始状态) (屏蔽后状态) RIS = Raw Interrupt Status ← 调试 / 轮询看这个 MIS = Masked Interrupt Status ← ISR 看这个 IMSC = Interrupt Mask Set/Clear ← 使能位（PrimeCell 里是高有效=使能） ICR = Interrupt Clear Register ← W1C
为什么要同时有 RAW 和 MASKED
RAW 用于调试和轮询：软件没开中断时也能查事件是否发生；出问题时能区分"事件没来"还是"事件来了被挡住"
MASKED 用于 ISR：ISR 只应处理自己使能了的源。若 ISR 直接读 RAW，会去处理那些被故意屏蔽的事件，导致行为错乱
两者都是必需的：只给一个会让软件无法区分状态，是寄存器设计的常见缺陷

4.2 enable 与 mask 的极性之争

命名语义复位值有效逻辑
INT_EN1 = 允许上报0（默认全关）raw & en
INT_MASK1 = 屏蔽1（默认全屏蔽）raw & ~mask

最容易出错的地方：复位默认值。无论用 EN 还是 MASK 命名，复位后必须是"中断全部关闭"。否则复位刚撤离、软件还没初始化好 ISR 和向量表，就被一个中断打进去，直接跑飞。

同一颗芯片里不要混用两种极性。有的模块叫 EN、有的叫 MASK，驱动工程师迟早写反一个。团队应在寄存器规范中统一选一种。

Set/Clear 分离寄存器：GIC 的 ISENABLER/ICENABLER、NVIC 的 ISER/ICER 用两个地址分别做"写 1 置位"和"写 1 清位"，好处是多核或多任务修改使能位时无需读-改-写，天然原子。强烈推荐在多核 SoC 的共享中断寄存器上采用这种形式。

4.3 屏蔽发生在哪一级

同一个中断在到达 CPU 前可能经过 5 个屏蔽点。调试"中断上不来"时，必须逐级往上查：

层级控制位关闭后的现象事件是否保留
L0 源级SRC_EN（若有）连 RAW 都不置位丢失
L1 模块INT_EN / INT_MASKRAW 有、STATUS 无、IRQ 不拉保留
L1 模块总开关MODULE_INT_EN同上保留
L2 聚合SUB_EN模块 STATUS 有、IRQ 不拉保留
L3 控制器ISENABLER / threshold / priority控制器 pending 有、不送 CPU保留
L4 CPUCPSR.I / PRIMASK / mstatus.MIEIRQ 线拉着但 CPU 不响应保留（IRQ 线持续）

排查口诀：读模块 RAW → 没有就是事件/捕获的问题（看 §5-§9）；RAW 有 STATUS 无 → 模块 mask；STATUS 有但控制器 pending 无 → 聚合层 SUB_EN 或连线接错；控制器 pending 有但不进 ISR → 控制器 enable / 优先级门限 / CPU 全局开关。每一层都提供可读的状态寄存器，是中断模块可调试性的基本要求。

4.4 优先级与抢占

概念说明硬件要点
优先级多个 pending 同时存在时谁先被服务ARM/RISC-V PLIC 数值小=优先级高（PLIC 相反，数值大=高），文档必须写清
抢占 Preemption高优先级中断能否打断正在执行的低优先级 ISR需要控制器维护 Active 状态和运行优先级栈
抢占分组优先级字段拆成"抢占级 + 子优先级"，同抢占级内不互相抢占NVIC 的 PRIGROUP、GIC 的 BPR
优先级门限低于门限的中断一律不送 CPUPLIC threshold、GIC PMR、Cortex-M BASEPRI
Tail-chaining连续中断之间不做出栈再入栈，直接切 ISRCortex-M 特性，显著降低背靠背中断开销
同优先级仲裁优先级相同时按中断号大小定必须是确定性的，不能用随机或轮转——否则无法验证

优先级反转：低优先级 ISR 持有自旋锁，高优先级 ISR 等锁，整个系统卡死。硬件侧能做的是：为关键中断（错误、看门狗）提供独立到 CPU 的通路，不与普通中断共用 pending/清除资源。

第 四 部 分

中断源的类型：电平还是脉冲

这是中断硬件设计中最核心的一个选择。选错或者上下游理解不一致，表现就是"中断丢了"或者"中断停不下来"。关键问题只有一个：事件信号自己能不能一直保持，直到软件来处理？

5. 电平型中断源

定义：中断请求信号在中断条件成立期间一直保持有效电平，条件消失后自动变回无效。信号本身就携带"当前状态"。

触发条件 ───┐ fifo_cnt >= threshold ┌─── 条件消失（软件读走数据） ▼ ▼ int_level ──┌──────────────────────────────┐───────── │ 持续拉高，直到根因消失 │ ───┘ └───────── 特点：① 信号 = 状态，不需要额外锁存 ② 软件任何时刻读都能看到真实情况 ③ "清中断" = "消除根因"，而不是写某个 bit

5.1 典型的电平型中断源

中断源有效条件何时自动撤销
UART RX FIFO 非空 / 水位到rx_cnt > level软件读走数据使 rx_cnt 降下来
TX FIFO 空 / 水位以下tx_cnt < level软件写入新数据
外部 nIRQ 引脚（开漏共享）从设备拉低软件通过 I2C/SPI 访问从设备清其内部状态后，从设备释放引脚
温度超限 / 电压异常比较器输出有效物理条件恢复
GPIO 电平中断引脚处于配置的电平外部信号变化
总线 / 模块 busy-error 保持态错误状态寄存器非 0软件清错误状态寄存器

优点说明

问题说明对策
无法表达"发生了 N 次"只知道"现在条件成立"，不知道期间发生了几次需要计数的场合（如溢出次数）必须另配计数器或用边沿型
瞬时事件无法表达"一次传输完成"这种只存在一拍的事件，没有可持续的状态必须转成锁存型（见 §8）

一次中断延迟较大需等待整个电平同步传播一般不是瓶颈

电平型 + 根因不可消除 = 死机。例如过温中断：温度降不下来，IRQ 一直拉着，CPU 从 ISR 一返回立刻再进，连降频的代码都跑不完。标准做法：ISR 第一件事就是屏蔽自己（写 mask），然后发一个标志给后台任务；任务完成降频/散热后再解除屏蔽。这个"自屏蔽"模式是电平型中断驱动的通用写法，硬件必须保证屏蔽位可被 ISR 快速写入且立即生效。

6. 脉冲 / 边沿型中断源

定义：中断请求是一个瞬时事件——持续一个（或几个）时钟周期的脉冲，或信号的一次跳变沿。事件本身不携带持续状态，必须被硬件锁存成 pending 位，否则 CPU 还没来得及响应，信号就消失了。

7.1 选型决策

这个中断的根因是"持续状态"还是"瞬时事件"？ │ ├── 持续状态（FIFO 有数据 / 错误状态寄存器非 0 / 条件成立） │ └──▶ 电平型 │ · 直接把条件接出来，不锁存 │ · 手册写明"清除 = 消除条件" │ · 驱动采用"ISR 自屏蔽"模式防风暴 │ └── 瞬时事件（完成 / 溢出 / 跳变 / 一次性错误） └──▶ 脉冲型 · 必须做 pending 锁存（set 优先） · 提供 W1C 清除端口 · 软件关心次数 ⇒ 加 overflow 标志 · 跨时钟域 ⇒ 先转电平再同步 实在拿不准时：做成脉冲型 + pending 锁存。 因为"事件一定不丢 + 清除路径明确"比什么都重要， 而电平型的行为总可以用"条件成立时持续置 pending"来模拟。

工业界的主流做法：模块内部统一用"锁存型 pending + W1C"（即对外表现为边沿/脉冲型），即使根因是电平状态也先锁存。少数确实需要"状态自洽"的源（FIFO 水位、共享 nIRQ）才保留电平型。这样整个 SoC 的中断行为一致，软件写法统一，GIC 配置也简单（绝大多数配成 edge）。

7.2 混合型：电平条件 + 边沿捕获

还有一类常见设计：根因是电平条件，但中断按条件的上升沿触发一次。

行为说明适用
条件 0→1 时置 pending 一次之后条件继续保持也不再置位"水位第一次越过阈值"这种只需通知一次的场景
软件清除后，条件仍为 1 也不再触发必须条件先掉下去再上来才再触发避免风暴

这种设计必须在手册里写得极其清楚，否则软件会困惑："FIFO 明明还有数据，为什么清了中断就不来了？"常见的补救是同时提供一个电平型的状态位供软件轮询确认。

8. 电平/脉冲转换电路

8.1 电平 → 脉冲（边沿检测）

把一个持续的电平条件转成一拍脉冲，用于触发锁存型 pending。

// 标准上升沿检测
reg cond_d;
always @(posedge clk or negedge rst_n)
    if (!rst_n) cond_d <= 1'b0;
    else        cond_d <= cond_sync;      // cond_sync 必须已同步过

wire rise_pulse = cond_sync & ~cond_d;     // 上升沿
wire fall_pulse = ~cond_sync & cond_d;     // 下降沿
wire both_pulse = cond_sync ^ cond_d;      // 双沿

cond_sync 必须是已经同步到本时钟域的信号。直接对异步信号做边沿检测，亚稳态会让 cond 和 cond_d 解析不一致，产生虚假脉冲——表现为"没动过的引脚莫名其妙报中断"。

8.2 脉冲 → 电平（锁存）

把一拍脉冲变成持续的 pending 电平，这是所有脉冲型中断的标准处理。

// set 优先的 pending 锁存（关键：set 的优先级高于 clear）
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        int_pending <= 1'b0;
    else if (event_pulse)           // ① 置位优先
        int_pending <= 1'b1;
    else if (clr_wr && wdata[0])    // ② 后判清除
        int_pending <= 1'b0;
end

8.3 脉冲展宽（跨到慢时钟域）

当源域比目的域快，一拍脉冲可能被慢时钟整个跳过。

// 方案 A：展宽成 N 拍（N > 慢时钟周期 / 快时钟周期 + 2）
reg [2:0] stretch;
always @(posedge fast_clk or negedge rst_n)
    if (!rst_n)            stretch <= 3'b0;
    else if (event_pulse)  stretch <= 3'b111;      // 重装
    else if (|stretch)     stretch <= stretch - 1'b1;
wire wide_pulse = |stretch;     // 再送两级同步器

// 方案 B：toggle 同步（更稳，不依赖频率比）
reg tog;
always @(posedge fast_clk or negedge rst_n)
    if (!rst_n)           tog <= 1'b0;
    else if (event_pulse) tog <= ~tog;
// 目的域：两级同步 + 边沿检测，还原出脉冲

方案 B（toggle）的限制是两次事件的间隔必须大于同步延迟，否则会丢事件。若事件可能背靠背，需要在源域加 pending 或用异步 FIFO/握手。中断场景通常事件稀疏，toggle 够用。

8.4 电平 → 电平（跨域）

电平型中断跨域最简单：两级同步器直接打两拍即可。因为电平持续时间远大于两个目的域周期，不存在丢失问题。这是电平型中断相对脉冲型的一大优势。

9. 中断源的跨时钟域与去抖

9.1 中断路径上的 CDC

场景风险处理
外设时钟域 → 寄存器(APB)时钟域脉冲丢失、亚稳态电平：两级同步；脉冲：toggle 或展宽后同步
外部引脚（完全异步） → 芯片内部亚稳态 + 毛刺 + 抖动同步器 + 数字滤波 + 可配极性
低功耗域 → 常开域（唤醒源）时钟已关，无法用同步器走异步唤醒通路（电平敏感），唤醒后再正常同步
多个异步源 OR 后再同步重汇聚：各位解析时刻不同产生毛刺必须先各自同步、再 OR，绝不能先 OR 后同步

先 OR 后同步是中断模块最隐蔽的 CDC Bug。多个异步源 OR 到一起再进同步器，两路同时跳变时组合逻辑产生毛刺，同步器可能采到虚假的 1（虚假中断）或错过真实的 1（丢中断）。正确顺序：每源 → 两级同步 → OR。

9.2 外部引脚中断的去抖滤波

// 计数型数字滤波：信号必须稳定 N 个周期才被认可
reg [7:0] cnt;
reg       filt_out;
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        cnt <= 8'd0; filt_out <= 1'b0;
    end else if (pin_sync == filt_out) begin
        cnt <= 8'd0;                       // 与当前认可值相同，计数清零
    end else if (cnt == DEBOUNCE_N) begin
        filt_out <= pin_sync;              // 持续不同够久，翻转
        cnt      <= 8'd0;
    end else begin
        cnt <= cnt + 1'b1;
    end
end
// filt_out 再送去做电平判断或边沿检测
滤波参数考虑
滤波宽度 DEBOUNCE_N必须 > 最长抖动时间（机械按键 ~10ms），但 < 最短有效脉冲宽度
可配置性做成寄存器可配，不同板子抖动特性不同
可旁路高速信号需要旁路滤波，提供 FILTER_BYPASS 位
滤波时钟低功耗场景滤波逻辑需跑在常开的低频时钟上

9.3 唤醒中断的特殊性

作为唤醒源的中断必须在时钟关闭时仍能工作，因此：

  • 唤醒通路必须是电平敏感的异步逻辑（或跑在常开的 32kHz 时钟上），不能依赖主时钟的同步器
  • 唤醒电平必须保持到时钟恢复、同步器工作起来为止，否则刚唤醒就失去了中断信息
  • 唤醒使能（WAKE_EN）和中断使能（INT_EN）通常是两套独立的位，可以"只唤醒不中断"或"只中断不唤醒"
  • 唤醒后 pending 必须仍然存在，软件才知道是谁唤醒的——需要常开域的 pending 寄存器
第 五 部 分

怎么清除中断

清除机制决定了 ISR 能不能正常退出。软件清、硬件清、自清除各有适用场景，但真正的难点不在"用哪种"，而在清除动作与新事件同时发生时的竞争——这是中断模块最容易出硅上 Bug 的地方。

10. 清除方式总览

方式谁发起机制适用风险
W1C 写 1 清软件软件向 INT_CLR 写 1 清对应位脉冲/边沿型的首选低，推荐
W0C 写 0 清软件写 0 清，写 1 保持极少用，历史遗留易与"写 0 无效"混淆
读清除 RC软件读状态寄存器的动作本身清除老 IP（8250 UART 的 IIR/LSR）高：调试器读一眼就丢中断
读某个数据寄存器清软件（间接）读 RX_DATA 自动清 RX 中断UART/SPI 的接收中断中：隐式副作用
硬件自清除硬件条件自动消失，软件不干预电平型、脉冲计数到期中：软件可能来不及看到
条件消失才清（电平型）硬件 + 软件间接软件消除根因，信号自然撤销电平型中断高：根因不消失就风暴
EOI / claim-complete软件控制器层的服务结束通知GIC/PLIC 必需漏做会卡住后续中断

推荐组合：模块级用 W1C（显式、无副作用、可重复、调试友好），控制器级用标准的 EOI/complete。这是当前主流 SoC 的默认选择。

10.1 软件写 1 清除（W1C）

最主流的清除方式。软件向清除寄存器的某位写 1，硬件把对应 pending 位清零；写 0 的位不受影响。

// W1C 的标准实现（注意 set 优先）
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        int_raw <= 32'b0;
    else
        int_raw <= (int_raw & ~clr_mask) | event_pulse;
                 //         ↑清除          ↑置位（后 OR，天然 set 优先）
end
assign clr_mask = (psel & penable & pwrite & (paddr == ADDR_INT_CLR)) ? pwdata : 32'b0;
W1C 的优点
按位独立：清 bit0 不影响 bit5，不需要读-改-写，天然原子，多任务/多核安全
无读副作用：状态寄存器可以被调试器、trace、多个任务任意读，不改变状态
幂等：重复写 1 清无害
语义明确：ISR 代码 INT_CLR = bit 一眼看懂

独立 CLR 寄存器 vs 状态寄存器自身 W1C：

  • 状态寄存器自身 W1C（读返回状态、写 1 清）：地址少，但读写语义不同，某些总线/编译器的读-改-写优化会误清其他位
  • 独立的只写 CLR 寄存器：状态寄存器纯 RO，语义最干净，推荐

10.2 读清除（Read-to-Clear, RC）

读取状态寄存器的动作本身就清除中断。常见于早期 IP（8250/16550 UART 的 IIR、LSR）。

读清除是强烈不推荐的设计，原因：

  • 调试器会破坏状态：JTAG 调试器刷新寄存器窗口、或在断点处显示外设寄存器，一读中断就没了，Bug 永远复现不出来
  • 无法重复读：ISR 想二次确认状态都做不到
  • 多个读者冲突：两个任务、或 ISR 与后台任务同时读，一方丢失信息
  • 读-改-写陷阱：C 代码里一个看似无害的 if (REG & BIT) 就触发了清除
  • trace / 性能分析工具同样会误触发

如果必须兼容老协议，务必在手册中用显著方式标注"读有副作用"，并提供一个无副作用的影子寄存器供调试使用。

10.3 硬件自清除

软件不需要显式清除，硬件在特定条件下自动把 pending 清零。

自清除场景触发条件说明
读数据寄存器自清软件读 RX_DATAUART/SPI 接收中断最常见；"处理了数据"等价于"处理了中断"，省一次寄存器写
写数据寄存器自清软件写 TX_DATATX 空中断：写了新数据就不再空
FIFO 水位自然回落cnt 低于阈值本质是电平型的自然撤销
控制器取号自清读 GIC IAR / PLIC claim边沿型中断在被 claim 时控制器侧 pending 自动清（注意：模块侧 pending 不会被清）
进入 ISR 自清Cortex-M NVIC 进入 ISR边沿型自动清 pending；电平型则取决于源是否撤销
单次脉冲自撤销脉冲发完自己变 0这不是合法的中断清除，因为软件根本没机会看到，等于丢中断

"读数据自清"的隐患：如果中断源是"FIFO 中有 ≥N 个数据"，软件只读了 1 个就自清，但 FIFO 里还有数据，此时中断条件仍成立却被清掉了 → 剩下的数据没人管。正确做法是让该中断保持电平型语义：清除条件是"水位降到阈值以下"，而不是"读了一次"。

绝不要做"硬件 N 拍后自动清 pending"这种设计。软件无法保证在 N 拍内响应，中断必丢。任何 pending 位的清除都必须由软件动作（直接或间接）触发，或由"根因消失"触发。

10.4 条件消失才清（电平型的清除）

电平型中断没有"清除寄存器"可写，清除就是消除根因。

中断ISR 必须做什么才能退出
RX FIFO 非空把 FIFO 读空（或读到水位以下）
TX FIFO 空写入新数据，或关掉该中断的 mask
外部 nIRQ 低通过 I2C/SPI 访问从设备，清它内部的状态寄存器，使其释放引脚
过温无法立即消除 → 必须靠屏蔽
错误状态保持写清错误状态寄存器（本质又回到 W1C）
电平型中断的标准 ISR 模式（自屏蔽）： ISR: ① 读 INT_STATUS 确认是哪个源 ② 写 INT_MASK 屏蔽该源 ← 关键：立刻停止重入 ③ 设置标志 / 唤醒后台任务 ④ 返回 后台任务: ⑤ 慢慢处理（读完 FIFO / 降频 / 访问外部从设备） ⑥ 确认根因已消失 ⑦ 写 INT_MASK 解除屏蔽 ← 若期间又有新事件，这里会立刻重新触发 注意 ⑦ 之前必须确认根因真的消失，否则解屏蔽瞬间又进 ISR。

外部共享 nIRQ 的延迟问题：从设备释放 nIRQ 需要经过 I2C 事务（可能几百微秒）+ 上拉电阻的 RC 上升时间。如果 CPU 在信号还没拉高时就退出 ISR，会立刻再次进入。对策：ISR 返回前读回确认引脚已释放，或采用自屏蔽模式。

10.5 EOI / 控制器侧清除

模块侧清 pending ≠ 控制器侧结束服务。ISR 必须两件事都做。

控制器取号结束漏做的后果
GIC读 GICC_IAR（返回 INTID，中断转为 Active）写 GICC_EOIR（降低运行优先级），GICv2 分离模式还需写 DIR 清 Active漏 EOI → 运行优先级一直很高，同级及以下中断全部被挡住，系统看似"只响应了一次中断就死了"
PLIC读 claim（返回 ID 并清该源 pending）写 complete（写回同一个 ID）漏 complete → 该中断源永久不再上报
NVIC硬件自动硬件自动（异常返回时）无需软件干预，这是 Cortex-M 的优势
完整的 ISR 清除顺序（电平型源 + GIC）： ① 读 IAR 取得 INTID ← 控制器层 ② 读模块 INT_STATUS 确定子源 ← 模块层 ③ 处理（读数据 / 排错） ④ 清模块中断（W1C 或消除根因） ← 模块层，必须在 EOI 之前 ⑤ 读回确认模块 IRQ 已撤销 ← 关键，电平型尤其重要 ⑥ 写 EOIR 结束 ← 控制器层 ⑦ 异常返回 顺序错了会怎样？ · ④⑤ 放到 ⑥ 之后 → 电平型 IRQ 还拉着，EOI 后立刻再次触发 → 风暴 · 漏 ⑥ → 后续同级中断全被挡住 · 漏 ⑤ → 写缓冲导致清除还没到达硬件就 EOI（见 §11.3）

11. 清除时序与竞争

11.1 写清与置位同拍的竞争

这是中断模块最重要的时序问题。软件写清除的那一拍，硬件恰好又来一个新事件，谁赢？

┌─ 软件写 INT_CLR ▼ clk ──┐ ┌─┐ ┌─┐ ┌─┐ └─┘ └─┘ └─┘ └─ clr ───┌───┐────── ① 清除请求 event ───┌───┐────── ② 新事件恰好同拍 清除优先（错误）：pending = 0 → 新事件被吞掉，永久丢失 置位优先（正确）：pending = 1 → 软件下次 ISR 还能看到，最多多进一次
// 正确：置位优先
always @(posedge clk or negedge rst_n)
    if (!rst_n)              pending <= 1'b0;
    else if (event_pulse)    pending <= 1'b1;   // ← set 在前
    else if (clr_req)        pending <= 1'b0;

// 或等价的位向量写法（OR 在最外层，天然 set 优先）
always @(posedge clk or negedge rst_n)
    if (!rst_n) int_raw <= '0;
    else        int_raw <= (int_raw & ~clr_mask) | event_vec;

// 错误：清除优先，会丢事件
always @(posedge clk)
    if (clr_req)             pending <= 1'b0;   // ← 新事件被吃掉
    else if (event_pulse)    pending <= 1'b1;

铁律：置位永远优先于清除。代价是"可能多进一次 ISR"（软件读 STATUS 发现没事做，直接返回，无害）；反之的代价是"永久丢一个中断"（可能导致 DMA 永远不完成、数据永远收不到），严重得多。

APB 写的哪一拍算清除：必须明确定义为 psel & penable & pwrite 的那一拍（ACCESS 相位），且清除脉冲只有一拍。若用 psel & pwrite（SETUP+ACCESS 两拍），清除窗口变宽，吞掉事件的概率翻倍。这是 RTL review 的必查项。

11.2 清除后仍反复进 ISR

原因诊断解决
电平型，根因没消除读 RAW 发现清了还是 1消除根因，或 ISR 自屏蔽
清了模块，没清聚合层的锁存模块 STATUS=0 但上层 IRQ 仍为 1聚合层不应锁存（见 §3.3）
漏了 EOI / complete控制器状态寄存器显示 Active补上 EOI
清了一个子源，还有别的子源 pendingSTATUS 还有其他位是 1ISR 循环处理所有置位的子源，而不是只处理第一个
GIC 配成 level 但源是脉冲pending 清不掉或行为诡异检查 ICFGR 与 RTL 一致性
多核都收到同一个中断多核同时进 ISR，一个清了另一个发现没事干ISR 必须能容忍"伪中断"（读 STATUS 为 0 直接返回）

ISR 必须能容忍伪中断（spurious interrupt）。读 STATUS 发现全 0 时，正确的做法是做完 EOI 直接返回，而不是报错或死循环。GIC 甚至专门定义了 spurious INTID 1023。这是鲁棒驱动的基本要求，硬件 spec 里应明确说明伪中断是可能发生的。

11.3 写缓冲导致的 ISR 重入

最隐蔽的中断 Bug 之一。ISR 写了 INT_CLR，但这次写被总线写缓冲（write buffer / posted write）缓存住了，CPU 不等写完成就继续执行并执行了异常返回。此时清除还没到达外设，IRQ 线仍然拉着，CPU 返回的瞬间立刻又被同一个中断打进来。

CPU: 写 INT_CLR ──▶ 写缓冲 ──(几十拍后)──▶ APB ──▶ 外设清 pending │ ▲ ▼ │ 立刻 eret ──▶ IRQ 仍为 1 ──▶ 再次进 ISR ──────────┘ (此时才清掉，但已多进一次) 严重时：若外设访问很慢（低速 APB / 跨多级桥），可能连进几十次 ISR。
解决手段说明归属
写后读回ISR 写完 INT_CLR 后读一次同一外设的任意寄存器，读操作不能被缓冲，会强制前面的写完成软件（最通用）
内存屏障DSB / fence，但对 posted write 不一定足够，仍推荐读回软件
外设侧不用 posted write中断寄存器所在区域配成 strongly-ordered / device-nGnRnE系统配置（MPU/MMU 属性）
硬件提供清除完成状态提供一个"清除已生效"的状态位供软件 poll硬件（较少见）
ISR 自屏蔽先屏蔽（屏蔽同样有写缓冲问题，但屏蔽+读回成本更低）软件

硬件 spec 的责任：在中断寄存器章节明确写上「写 INT_CLR 后必须读回本模块任一寄存器以确保清除已生效，再执行中断返回」。这一句话能省掉驱动团队几周的调试时间。

11.4 事件合并与丢失计数

pending 已为 1 时又来一个事件，第二个事件被"吸收"，软件无法得知。

场景是否可接受处理
FIFO 水位中断（电平型）可接受软件读 FIFO 直到空，次数无意义
DMA 描述符完成不可接受需要完成计数器，或用描述符链表让软件遍历
ECC 纠错不可接受配事件计数器 + 饱和标志
FIFO 溢出错误一般可接受只需知道"发生过溢出"
外部中断视场景需要时加 INT_OVERFLOW 位：pending 为 1 时又来事件则置位
// 带丢失标志的 pending
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        pending <= 1'b0; overflow <= 1'b0;
    end else begin
        if (event_pulse && pending && !clr_pending)
            overflow <= 1'b1;            // 清之前又来了，记一笔
        else if (clr_overflow)
            overflow <= 1'b0;

        if (event_pulse)        pending <= 1'b1;
        else if (clr_pending)   pending <= 1'b0;
    end
end

12. 可综合参考实现

一个标准的模块级中断单元，支持每位可配电平/边沿、RAW/EN/STATUS/CLR 四件套、置位优先、overflow 标志。

module int_ctrl #(
    parameter int N = 8
)(
    input  logic         clk,
    input  logic         rst_n,

    // 中断源（已同步到 clk 域）
    input  logic [N-1:0] src_i,          // 电平型源：条件成立时为 1
    input  logic [N-1:0] pulse_i,        // 脉冲型源：事件发生时一拍 1

    // 寄存器接口（APB 简化）
    input  logic         wr_en_clr,      // 写 INT_CLR 的 ACCESS 拍
    input  logic [N-1:0] wdata_clr,
    input  logic         wr_en_mask,
    input  logic [N-1:0] wdata_mask,
    input  logic [N-1:0] cfg_edge_mode,  // 1=边沿捕获, 0=电平直通

    output logic [N-1:0] int_raw_o,      // RIS
    output logic [N-1:0] int_mask_o,     // IMSC (1=使能)
    output logic [N-1:0] int_status_o,   // MIS
    output logic [N-1:0] int_ovf_o,      // 丢失标志
    output logic         irq_o
);

    // ---------- 1. 事件捕获：电平转边沿 ----------
    logic [N-1:0] src_d, src_rise, event_vec;

    always_ff @(posedge clk or negedge rst_n)
        if (!rst_n) src_d <= '0;
        else        src_d <= src_i;

    assign src_rise  = src_i & ~src_d;                 // 上升沿
    assign event_vec = (cfg_edge_mode & (src_rise | pulse_i))
                     | (~cfg_edge_mode & src_i);       // 电平模式直接用电平

    // ---------- 2. pending 锁存：置位优先 ----------
    logic [N-1:0] clr_vec;
    assign clr_vec = wr_en_clr ? wdata_clr : '0;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            int_raw_o <= '0;
        else
            // 电平模式：条件为 1 时持续置位，条件消失后可被清（或自然为 0）
            // 边沿模式：事件置位后保持，必须软件清
            int_raw_o <= (int_raw_o & ~clr_vec) | event_vec;
            //                      ↑清除            ↑置位（OR 在外层 = set 优先）
    end

    // ---------- 3. 丢失标志 ----------
    always_ff @(posedge clk or negedge rst_n)
        if (!rst_n) int_ovf_o <= '0;
        else        int_ovf_o <= (int_ovf_o & ~clr_vec)
                               | (event_vec & int_raw_o & ~clr_vec);

    // ---------- 4. 屏蔽：复位默认全关 ----------
    always_ff @(posedge clk or negedge rst_n)
        if (!rst_n)           int_mask_o <= '0;        // 0 = 禁止，复位安全
        else if (wr_en_mask)  int_mask_o <= wdata_mask;

    // ---------- 5. 输出 ----------
    assign int_status_o = int_raw_o & int_mask_o;
    assign irq_o        = |int_status_o;               // 纯组合 OR，不再锁存

endmodule
实现要点回顾对应章节
事件捕获前必须已同步（src_i 是同步后的）§9
边沿检测用 src & ~src_d，不直接用异步信号§8.1
pending 置位优先（OR 放最外层）§11.1
mask 复位为 0（全禁止）§4.2
irq_o 是纯组合 OR，不再二次锁存§3.3
同时输出 RAW 和 STATUS§4.1

14.2 SVA 断言

// (1) 事件发生后 pending 必须置位（除非同拍被清且清除优先——本设计不允许）
property p_event_sets_pending;
    @(posedge clk) disable iff (!rst_n)
        event_vec[i] |=> int_raw_o[i];
endproperty
a_set_prio: assert property (p_event_sets_pending)
    else $error("INT: event lost, set priority violated!");

// (2) 未发生事件时 pending 不能自己置位
property p_no_spurious_set;
    @(posedge clk) disable iff (!rst_n)
        (!int_raw_o[i] && !event_vec[i]) |=> !int_raw_o[i];
endproperty
a_no_spurious: assert property (p_no_spurious_set);

// (3) pending 只能被 clr 清除（边沿模式）
property p_clr_only;
    @(posedge clk) disable iff (!rst_n)
        (int_raw_o[i] && cfg_edge_mode[i] && $fell(int_raw_o[i]))
            |-> $past(clr_vec[i]);
endproperty
a_clr_only: assert property (p_clr_only)
    else $error("INT: pending cleared without software clear!");

// (4) 屏蔽状态下 IRQ 不能拉高
a_mask_works: assert property (@(posedge clk) disable iff (!rst_n)
    (int_mask_o == '0) |-> !irq_o);

// (5) STATUS 必须等于 RAW & MASK（组合一致性）
a_status_eq: assert property (@(posedge clk)
    int_status_o == (int_raw_o & int_mask_o));

// (6) 解除屏蔽后，若 RAW 有效则 IRQ 必须拉起（事件不丢）
property p_unmask_reassert;
    @(posedge clk) disable iff (!rst_n)
        ($rose(int_mask_o[i]) && int_raw_o[i]) |-> irq_o;
endproperty
a_unmask: assert property (p_unmask_reassert);

// (7) 复位后 mask 必须全 0（中断全关）
a_rst_mask: assert property (@(posedge clk)
    $rose(rst_n) |-> (int_mask_o == '0));

全文一句话总结：中断设计的正确性归结为三个判断——源是状态还是事件（决定电平型还是脉冲型，进而决定要不要锁存）、每一层的放行与拦截是否可见可控（RAW/MASK/STATUS 齐全、只锁存一次、逐级可查）、清除动作与新事件竞争时谁赢（必须置位优先，且软件清除要考虑写缓冲）。这三件事做对，中断就不会丢、不会卡、不会风暴。
